# 채팅 GPT식 앱호스트 — 차이 조사

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-CR-20261117-GPTHOST |
| 작성일 | 2026-11-17 |
| 관련 | `app.present_html`, App Host 카드, GPT Apps / Canvas |
| 대상 | 「계산기 만들어줘」 테스트에서 본 별도 패널·빈 화면 |
| 목적 | Iris 현황과 최신 GPT 채팅 표현의 차이를 고정하고 개선 빈자리를 적는다 |

## 1. 결론

계산기 요청은 `app.present_html`까지 갔고 App Host 카드도 열렸다.  
다만 카드에 올린 HTML이 **완성 문서가 아니라 CSS 중간에서 잘린 조각**이라 본문이 비어 보였다.  
「별도 창」 체감은 OS 팝업이 아니라, GPT처럼 **메시지 안 인라인 iframe**이 아니라 **로그와 입력창 사이 슬롯**에 두는 현재 계약 때문이다.

| 증상 | 판정 | 근거 |
|---|---|---|
| 채팅과 분리된 앱 면 | 설계 차이 (버그라기보다 배치 계약) | `show_app_host` docstring, `AppHostCard` 주석 |
| 카드 안이 비어 보임 | 페이로드 결함 (루트) | ephemeral HTML에 `</body>`/`button` 없음, CSS 반복 후 절단 |

| 직전 시도도 미완성 (`linearinvoke…`) | 동일 폴더 18:44 파일 |

## 3. 구조

요청이 화면까지 가는 경로. 이번 증상이 갈라지는 지점을 `★`로 표시한다.

```text
사용자 「계산기 만들어줘」
        │
        ▼
Hermes / SpeakTools
   └─ app.present_html({ title, html })
        │
        ▼
ephemeral_offer
   └─ %TEMP%/iris-app-ui/ephemeral/<hash>-<id>.html
        │  ★ 여기에 잘린·반복된 HTML이 그대로 기록됨
        ▼
ChatPanel.present_chat_app_offer
   ├─ show_app_host(html_path) → AppHostCard (로그↔입력 사이 슬롯)
   └─ append_app_note 「다시 보기」 한 줄 (로그 안)
        │
        ▼
AppHostCard.show_offer → QWebEngineView.load(file://…)
   └─ ★ 미완성 HTML → 버튼·본문 없음 → 빈/어두운 면
```

| 갈래 | Iris 지금 | 최신 GPT (2025–2026) |
|---|---|---|
| 풍부한 텍스트 | MD → `chat_renderer` → QTextEdit (표·수식·matrix) | 채팅 안 writing/code 블록, 풍부 마크다운 |
| 조작 가능 앱 | App Host **슬롯** (로그 밖) + 로컬 HTML | MCP Apps **인라인 iframe** (기본), 선택적 PiP/fullscreen |
| 문서/캔버스 | 해당 제품면 없음 (다이어그램 카드는 별 슬롯) | Canvas는 현행 모델에서 축소·인라인 블록으로 이동, Apps SDK로 위젯 강화 |
| 데이터 계약 | `html` 문자열 통째이 도구 인자 | 도구 결과 + `_meta.ui.resourceUri` / 위젯 템플릿 (data·render 분리 권장) |

## 4. 코드 리뷰

| 지점 | 이번 증상에서 한 일 | 막지 못한 이유 |
|---|---|---|
| `iris_agent_memory_nudge` 22c | 계산기는 `app.present_html` 쓰라고 지시 | 모델이 경로를 따름. **완성 HTML**까지 강제하지 않음 |
| `app.present_html` | ephemeral 파일 쓰고 카드 open | 비어 있지 않으면 OK. `</html>`·본문 검증 없음 |
| `ephemeral_offer` | TEMP에 바이트 기록 | 크기 상한만. 절단·반복 루프 미검출 |
| `AppHostCard` | 로컬 file URL 로드 | 호스트는 파일을 그림. 내용이 비면 빈 면 |
| `show_app_host` 배치 | 로그·입력 사이 insertWidget | 의도적으로 메시지 버블 밖 → 「별도 창」 체감 |
| `chat_renderer` / GPT식 P0 | 표·수식 표시 | 인터랙티브 앱 경로와 분리. 계산기를 마크다운으로 해결하지 않음 |

### 하지 않은 일 (이번 조사 범위)

- App Host를 메시지 타임라인 인라인으로 옮기는 구현
- 잘린 HTML 자동 복구
- GPT Apps SDK / `window.openai` 프로토콜 전면 이식

## 5. 개선안

구조에서 빈 자리만.

| 우선 | 빈 자리 | 제안 |
|---|---|---|
| P0 | 미완성 HTML도 `shown:true` | `app.present_html` 경계에서 문서 완성 검사 (`<!DOCTYPE`/`</html>` 또는 `</body>` + 최소 interactive 힌트). 실패면 도구 에러로 재생성 유도 |
| P0 | 모델 HTML 폭주·절단 | 짧은 템플릿(계산기·타이머) builtin + `app.open`, 또는 data JSON + 고정 셸 HTML (GPT data/render 분리) |
| P1 | 「별도 창」 UX | 카드를 **해당 턴 메시지에 시각적으로 붙인 인라인 카드**로 (슬롯이어도 로그 스크롤과 한 덩어리로 보이게). 장기적으로는 버블 안 호스트 또는 하이브리드 로그 |
| P1 | display mode | GPT와 같이 `inline` / `pip` / `fullscreen` 계약. 기본은 인라인·작은 높이 |
| P2 | 풍부 답변 면 | 기존 GPT식 표현(P0 matrix 등)과 App Host를 한 제품 이야기로. 조작 UI만 호스트, 설명은 버블 |
| P2 | 관측 | present 직후 `loadFinished`·본문 길이·`button` 유무를 로그. 빈 면이면 사용자에게 「HTML이 불완전」 명시 |

## 6. 차용

| 이름 | 가져올 부분 | 이번에 가져오지 않는 이유 |
|---|---|---|
| OpenAI Apps / MCP Apps UI | `_meta.ui.resourceUri`, 인라인 기본, display mode, data/render 분리 | Iris는 이미 로컬 SpeakTools `app.present_html`이 있음. 프로토콜 전체보다 **배치·완성 검사·템플릿**이 급함 |
| openai-apps-sdk-examples | 위젯을 짧은 템플릿으로 두고 도구는 데이터만 | 예제 앱 전체를 넣지 않음. 패턴만 |
| Claude Artifacts | 모델이 페이지를 통째 씀 | GPT 현행은 Apps(개발자 위젯) 쪽. Iris 빈 화면은 모델 HTML 품질 문제라 템플릿·검증이 더 맞음 |
| 기존 Iris `diagram_card` | 로그 밖 카드 + 「다시 보기」 | 이미 App Host가 동일 배치. 인라인 목표와는 반대 방향 |

## 7. 조치

1. 구현 전: P0 완성 HTML 가드 + 계산기 builtin/템플릿을 Feature로 쪼갤지 결정.
2. UX 목표를 「GPT 인라인 앱」으로 고정하면 P1 배치 변경이 필수. 슬롯만 유지하면 체감 차이가 남는다.
3. 재현 확인: 동일 ephemeral 파일을 `AppHostCard`에 올리면 빈 면이 재현된다. 완성 `_CALC_HTML`을 올리면 버튼이 보인다.
