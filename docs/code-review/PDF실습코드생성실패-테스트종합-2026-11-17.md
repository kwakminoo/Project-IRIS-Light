# PDF 실습코드 생성 실패 — 테스트 종합

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-CR-2026-11-17-LAB-PDF |
| 작성일 | 2026-11-17 |
| 관련 | IDE-PDF빈화면과-첨부실습코드-원인, lab_script_dump, tool_error_budget |
| 대상 | `컴퓨터비전_08_백찬은.pdf` + 「모든 실습 코드 생성」 테스트 로그 |
| 목적 | 증상·원인·왜 그렇게 도는지·고칠 곳을 한 표로 고정 |

## 1. 결론

첫 실패는 모델이 아니라 **앱 전용 lab-dump**가 돌았고, **이 PDF의 라벨·코드 형태가 파서 가정과 달라** 「라벨을 찾지 못했습니다」로 끝났다.  
이후 「다시 진행해줘」는 lab-dump 의도가 아니어서 Hermes가 PDF를 직접 풀려다 **도구 한도·bash 인용·첨부 id·확인 대기·에러 예산**에 연쇄로 막혔다.

실측 (`컴퓨터비전_08_백찬은.pdf`, 45쪽, ~3.0MB):

| 측정 | 값 |
|---|---|
| 글자층에 `프로그램` | 0회 |
| 글자층에 `N-M` 단독 라벨 (`9-2` 등) | 0회 |
| 글자층에 `import` / `cv2` / `def ` | 0회 |
| 실습 제목 형태 | `(실습) YOLO v3으로…`, `(실습) pixellib…` |
| 실습 쪽 | 제목은 글자, **코드는 이미지**(쪽당 이미지 2~3) |

## 2. 요청이 가는 길

```
칩 PDF + 「실습 코드 생성/모두 만들어」
  ├─ is_lab_dump_intent?  (실습+생성/모두) + pdf_paths_from(attachments)
  │     └─ YES → LabDumpWorker → dump_lab_scripts
  │              → read_pdf_pages → parse_lab_programs(_LABEL_RE)
  │              → write_project_file → 「저장했습니다 / 라벨 없음」
  │              ※ Hermes 미호출
  └─ NO (예: 「다시 진행해줘」만)
        → AttachmentWorker / Hermes 도구 루프
              local.read_file / terminal / write_file /
              attachment.copy_to / project.import_attachment /
              content.dump_lab_scripts(넛지) …
```

이번 로그의 갈림:

| 턴 | 갈림 | 결과 |
|---|---|---|
| PDF + 「모든 실습 코드 생성」 | lab-dump | 라벨 0 → 오류 문구 |
| 「다시 진행해줘」 / 재시도·모델 전환 | Hermes | 도구 연쇄 실패 → 중단 |

## 3. 증상 표 (원인 · 왜 · 고침)

| # | 로그 증상 | 1차 원인 (measured) | 왜 이렇게 동작하나 | 고치는 방향 |
|---|---|---|---|---|
| 1 | `PDF에서 실습 프로그램 라벨을 찾지 못했습니다` | `_LABEL_RE`는 `프로그램 N-M` / 줄 단독 `N-M`만 인정. 이 PDF는 `(실습) …` 제목만 있음 | lab-dump는 **7주차식 「프로그램 7-5」** PDF용으로 설계됨. 본문 코드를 모델에 넣지 않으려고 라벨 경계로만 자름 | `(실습)` / 주차별 제목 파서 추가. 또는 라벨 0일 때 「이 PDF는 N-M 라벨이 없고 코드가 이미지입니다」로 **이유를 명시** |
| 2 | 코드 본문이 비어 저장 불가 (같은 뿌리) | 실습 쪽 코드는 **이미지**. 글자층에 `import` 등 없음 | `read_pdf_pages`는 글자≥40이면 OCR·비전을 건너뜀. 비전은 기본 **4쪽**만 | 실습 쪽은 이미지 코드 전제로 OCR/비전 강제. 쪽 수 한도를 실습 덤프 전용으로 완화. `project.write_image_code` 경로와 연결 |
| 3 | 「다시 진행해줘」가 또 실패 | `is_lab_dump_intent`에 생성/실습 단서가 없음 → Hermes | 의도 재시도 문장은 앱 인터셉트를 안 탐 | 직전 턴이 lab-dump 실패면 「다시」를 같은 파이프로 재실행. 또는 실패 답에 `content.dump_lab_scripts` 재시도 안내 |
| 4 | `local.read_file` 한도 초과 (1MB / 5000) | PDF 3MB. 도구는 **텍스트 전용**, 기본 상한 1MB. 모델이 `max_bytes=5000`을 주면 그 한도 | 바이너리 PDF를 텍스트 리더로 읽게 한 모델 실수 + 안전 한도 | PDF는 `content.extract` / `content.dump_lab_scripts`만. `local.read_file`이 `.pdf`면 즉시 「바이너리/전용 도구」 거절 |
| 5 | bash `EOF`/`import: command not found` / `python -c` 문법 오류 | Hermes `terminal`이 **bash eval**로 멀티라인·따옴표를 깨뜨림 | Windows 경로·heredoc을 bash 한 줄 eval에 넣으면 줄마다 셸 명령이 됨 | 멀티라인 Python은 `execute_code` / 파일 기록 후 실행만. 또는 terminal에 Windows PowerShell argv 경로 |
| 6 | `Refusing to overwrite … never read / offset pagination` | Hermes `write_file` 정책. 부분 read 후 전체 덮어쓰기 거부 | 에이전트 안전장치. 모델이 같은 임시 스크립트를 반복 patch | lab 경로에서는 `write_file` 우회 금지. `content.dump_lab_scripts` / `project.write_file`만 |
| 7 | `interrupted_by_system(tool_error_budget)` | 동일 오류 3회 또는 턴 총 오류 10회면 hard cancel | `ToolErrorBudget`이 무한 루프를 막음. 이번엔 원인 미해결 재시도로 예산 소진 | 예산 자체는 유지. **같은 실패 클래스면 조기 중단 메시지**에 다음 행동 1개만 제시 |
| 8 | `search_files` `rg: (?:*.py)` 파싱 오류 | 모델이 파일 glob을 **정규식**으로 넣음 | ripgrep 패턴과 Hermes 파일 필터가 다름 | 도구 쪽에서 glob/regex를 분리해 검증. 잘못된 패턴은 즉시 거절 |
| 9 | `attachment_copy_to` 420초 타임아웃 | `confirm_required=True`. 사람 확인/UI 대기가 Hermes 순차 도구 한도까지 감 | 외부 경로 복사는 확인 UX가 필요. 모델은 id만 알고 확인창을 못 닫음 | 워크스페이스 안 `project.import_attachment` 우선(확인 없음). copy_to는 확인 대기 중임을 도구 결과에 명시 |
| 10 | `project.import_attachment` 「첨부파일을 찾을 수 없습니다」 | `AttachmentStore.roots`에 없는 `attachment_id`. 새 채팅·미등록·파일명 오인 | 첨부는 **세션 store의 uuid**. 경로 문자열·파일명이 id가 아님 | 칩 첨부 시 id를 모델에 노출. 또는 파일명→id resolve. 새 채팅이면 「다시 첨부」 |
| 11 | `project_open_similar` 엉뚱한 폴더 / low_score | 쿼리 「컴퓨터비전」이 다른 최근 폴더와 매칭 | similar는 점수 기반. 실습 생성과 무관 | lab-dump 전용 경로에서는 open_similar 금지. 이미 bound workspace 사용 |
| 12 | 429 / 503 / structured output 실패 | Cerebras TPM, NVIDIA safety/overload, gpt-oss 스키마 | 무료·공유 API 한도. 도구 루프가 토큰을 크게 씀 | PDF 실습은 **앱 경로로 끝내** API 호출을 줄임. 모델 전환 시 긴 히스토리 재전송 축소 |
| 13 | 파일 정리 중 `calendar_list_events` | 모델이 무관 SpeakTool을 호출 | 카탈로그에 캘린더가 보이면 환각 호출 가능 | 턴 의도 태그에 허용 도구 축소 (이미 일부 넛지 있음) |

## 4. 코드 리뷰 (손댄 경로)

| 지점 | 이번 테스트에서 한 일 | 요청을 막지 못한 이유 |
|---|---|---|
| `main_window._try_local_lab_dump` | 의도 맞으면 Hermes 전에 LabDumpWorker 기동 | 파서가 이 PDF 형태를 모름 |
| `lab_script_dump._LABEL_RE` / `parse_lab_programs` | `프로그램 N-M`만 매칭 | `(실습) …` · 이미지 코드 미지원 |
| `content_extract.read_pdf_pages` | 글자층 우선, 비전 4쪽 | 실습 코드가 그림이면 본문 미추출 |
| `local_files.local_read_file` | 텍스트·1MB 한도 | PDF 바이너리 읽기 시도에 적합한 거절이 약함 |
| `attachment_store._transfer_source` | 없는 id → 「첨부파일을 찾을 수 없습니다」 | 모델에 id 계약이 약함 |
| `attachment.copy_to` + confirm | 사람 확인 대기 | 420초까지 도구가 멈춤 |
| `tool_error_budget` | 반복 실패 시 턴 강제 종료 | 올바른 안전장치. 근본 수정은 아님 |
| Hermes terminal / write_file | 모델이 PDF를 셸로 풀려 함 | lab-dump 실패 후 우회 경로. 설계상 비권장 |

하지 않은 일: IDE PDF 뷰어, 위키 import, Companion 타일.

## 5. 구조상 빈 자리 → 개선 순서

1. **실패 메시지에 PDF 형태 진단** (라벨 0 / 이미지 코드 추정) — 최소, 즉시.
2. **이 강의 형식 지원**: `(실습) 제목` 블록 + 쪽 이미지 OCR/비전으로 코드 추출 → `labs/<slug>.py`.
3. **재시도 의도**: 「다시」「이어서」가 직전 lab-dump 실패에 묶이면 같은 Worker 재실행.
4. **Hermes 우회 억제**: lab PDF 의도에서는 terminal로 PyMuPDF/pdfplumber 금지 넛지 강화. `content.dump_lab_scripts`만.
5. **첨부 id**: 칩 메타를 도구 스키마/상태에 포함해 import_attachment 오인 감소.

## 6. 차용

| 이름 | 가져올 부분 | 이번에 안 가져오는 이유 |
|---|---|---|
| 기존 `read_pdf_pages` + Tesseract | 이미지 쪽 OCR | 이미 저장소에 있음. lab-dump에만 연결 부족 |
| `project.write_image_code` | 스크린샷→코드 쓰기 | 쪽 단위 배치와 파일명 규칙이 다름 |
| Marker / Nougat 등 PDF→MD | 학술 PDF 구조화 | 의존성·지연 큼. 강의 슬라이드 이미지 코드에는 과함 |
| 찾지 못함 | `(실습)` 라벨 전용 오픈소스 파서 | 강의 자료 맞춤. 로컬 규칙으로 충분 |

## 7. 조치

1. 사용자 확인: 이 8주차 PDF는 **「프로그램 9-2」 텍스트 라벨이 없고**, 실습 코드는 **슬라이드 이미지**다.
2. 수정 우선순위는 위 5절 1→2→3. Hermes 터미널 우회를 고치는 것은 부차다.
3. 검증: `_check_lab_script_dump`에 `(실습)` 샘플 + 이미지 코드 쪽 fixture 추가 후, 같은 PDF로 LabDumpWorker 재실행.
