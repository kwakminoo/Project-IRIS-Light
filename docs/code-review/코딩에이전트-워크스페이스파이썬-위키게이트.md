# 코딩 에이전트: 워크스페이스 파이썬 · 위키 게이트

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-CR-2026-11-03-coding-agent-env |
| 작성일 | 2026-11-03 |
| 관련 | 컴퓨터비전 `7-7.py` ModuleNotFoundError, Wiki Import 오탐 |
| 대상 | `project.run` / IDE ▶ / `wiki_save_intent` |
| 목적 | Cursor처럼 워크스페이스에 의존성을 묶고, 코딩 턴이 위키로 새지 않게 함 |
| 제외 | P2 24k 예산·칩 비전 확대 (다른 작업) |

## 1. 결론

Iris가 코딩 에이전트로 동작하려면 **실행·pip·IDE Run이 같은 워크스페이스 인터프리터**를 써야 한다. 위키 저장은 **문서 의도일 때만** 로컬 가로채기를 쓰고, 오류 로그·`.py` 첨부는 에이전트에 넘긴다.

## 2. 구조

```text
사용자 / Hermes
  ├─ project.run / pip  → ensure_project_python(root) → .venv\Scripts\python.exe
  ├─ IDE ▶ (iris.ide.runFile) → workspace/.venv 우선(walk-up), 없으면 PATH python
  └─ 채팅 턴
       ├─ documents_only 위키 게이트 → PDF·md 등만 (코드 확장자 제외)
       └─ 그 외 → Hermes 도구 (project.run, wiki.import_* …)
```

`project.run` 바인딩은 `27d2021`. IDE ▶ 바인딩은 `iris-ide-project-python.ts` + Run 툴바.
남은 갈라짐: `_SAVE_WORDS`의 `"import"` + 첨부(위키 오탐).

## 3. 코드 리뷰

| 지점 | 이번 증상에서 한 일 | 막지 못한 이유 |
|---|---|---|
| `build_run_command` | `.py` → `["python", rel]` | PATH 첫 python. Hermes site-packages와 무관 |
| IDE `RUNNERS.py` | 동일 bare `python` | 위와 같음 |
| Hermes venv | pip으로 tensorflow 설치 | Run이 그 경로를 안 씀 |
| `is_wiki_save_intent` | 첨부+`import` 부분문자열 → 저장 의도 | 트레이스백 `import tensorflow` 오탐 |
| `_try_local_wiki_save(documents_only=True)` | Hermes 전에 턴 종료 | `.py`도 source로 허용 |

하지 않은 일: 24k/`VISION_PAGE_CAP`, Hermes 셸 툴셋 전면 개편, 위키 규칙 전부 삭제.

## 4. 개선안

1. `ensure_project_python(root)` — `.venv` 없으면 생성, 있으면 재사용. `build_run_command`·`project.run` argv의 `python`을 절대경로로 바인딩.
2. IDE Run 툴바가 `cwd/.venv/Scripts/python.exe`(또는 `bin/python`)를 우선.
3. `_SAVE_WORDS`에서 `"import"` 제거. `documents_only`는 `_NOTE_EXT`·URL만 가로채기.

## 5. 차용

| 이름 | 가져올 부분 | 이번에 안 가져오는 이유 |
|---|---|---|
| Cursor / VS Code Python | 워크스페이스 인터프리터 선택 | 설정 UI·멀티 인터프리터 피커는 과함. `.venv` 고정만 |
| PEP 405 venv | `python -m venv` | stdlib로 충분 |
| 찾지 못함 | 트레이스백 전용 위키 차단 오픈소스 | 자체 `_NOTE_EXT` 필터로 충분 |
