# 채팅 GPT식 전사 — 목표 아키텍처 조사

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-CR-20261117-GPTTRANSCRIPT |
| 작성일 | 2026-11-17 |
| 관련 | `채팅-GPT식표현-구현설계.md`(P0 matrix·C단계 보류), `채팅-GPT식앱호스트-차이조사-2026-11-17.md` |
| 대상 | 최신 ChatGPT식 **채팅 안 블록·풍부 레이아웃·인라인 조작**을 Iris 답변에 들이려면 무엇을 바꿔야 하는가 |
| 목적 | 최소구현(표 색칠·슬롯 카드)이 아니라 **목표 제품면**을 고정하고 수정 경계를 적는다 |

## 1. 결론

GPT식 답변은 「마크다운을 조금 더 예쁘게」가 아니다.  
**typed message parts**로 턴을 만들고, 그 파트를 **채팅 전사(transcript) 안에서** 각기 다른 호스트(편집기·프리뷰·앱 iframe)로 그린다.

Iris는 지금 정본이 `chat_messages.content: str`(평문/MD)이고, 화면은 `MD → sanitize HTML → QTextEdit.insertHtml` 한 줄이다.  
이 천장 안에서는 writing block, Code/Preview, 인라인 앱, 브라우저급 레이아웃이 **원리적으로** 안 나온다.  
이전 설계의 C단계(WebEngine 채팅) 보류를 유지한 채 P0만 키우면, 사용자 체감은 GPT에 수렴하지 않는다.

| 판단 | 내용 |
|---|---|
| 목표 데이터 | `Message = list[Part]` (`text` / `writing` / `code` / `tool` / `image` / `app` / `citation` …) |
| 목표 호스트 | QTextEdit 단일 로그 **폐기 또는 부속**. 전사 본체는 WebEngine 문서 **또는** 메시지 위젯 리스트 |
| 하지 말 것 | QTextEdit sanitize 확장만으로 GPT 패리티를 기대하는 것 |
| 선행 문서와의 관계 | 2026-10-19 설계의 P0는 **표시 응급처치**. 본 문서는 그 상한 위의 **재설계** |

## 2. 확인한 사실 (Iris 지금)

| 사실 | 근거 |
|---|---|
| 제품 정본은 SQLite `chat_messages` | `iris/runtime/chat_canonical.py` |
| 행 형태: `role`, `content`, `model_content` 문자열 | `iris/storage/conversations.py` `ChatMessage` |
| typed parts 테이블/JSON 컬럼 없음 | 스키마 `CREATE TABLE chat_messages` |
| 워커 본문은 `content_chunk(str)` / `finished_ok(str)`. 앱은 옆길 `app_ui(...)` | `iris_agent_workers.py` ([Iris chat render map](25d9483c-6d76-470c-93e2-2af209695586)) |
| `ChatBlockBuffer`는 스트림 문자열을 prose/code/tool로 자를 뿐 저장 스키마가 아님 | `iris/core/chat_block_parser.py` |
| `model_content`는 모델용 별도 본문. UI typed parts가 아님 | `ChatMessage.model_content` |
| thinking은 Live Activity. 전사 블록이 아님 | `_on_thinking_*` → Live Activity |
| 렌더: `render_iris_message` → MD → `_sanitize_chat_html` → `insertHtml` | `chat_renderer.py`, `chat_panel.py` |
| sanitize가 `script`/`style`/`iframe`/`svg`/`math`/`form` 드롭 | `_DROP_WITH_CONTENT` |
| 허용 태그는 HTML4 부분집합 (`div`도 없음, `span`/`table`/`pre` 등) | `_ALLOWED_CHAT_TAGS` |
| 코드 「카드」는 HTML 테이블·앵커(`iris-copy://`)지 CodeMirror/Preview가 아님 | `chat_blocks.fenced_code_to_html`, `card_html` |
| `ChatBlockKind`는 prose/fence/tool 등 **도메인 힌트**가 있으나 최종은 다시 HTML 문자열 | `chat_blocks.py` |
| 스트림은 문자열 버퍼 + block/타이핑으로 QTextEdit 본문 교체 | `begin_stream_message` / `append_stream_chunk` |
| App Host·Diagram은 로그 **밖** 슬롯 | `app_host_card.py`, `diagram_card.py` docstring |
| Qt rich text는 둥근 버블·CSS 레이아웃 신뢰 불가 | `render_user_message` 주석, `chat_syntax.py` |

## 3. 최신 GPT 제품면 (목표 기준)

출처: OpenAI Help(writing/code blocks), ChatGPT Web 역설계(performance.dev), Apps UI 문서, 이전 앱호스트 조사.

| 면 | GPT가 하는 일 | Iris 대응 여부 |
|---|---|---|
| 메시지 = parts | text / code / execution_output / multimodal 등 | 없음. 단일 `content` |
| Writing block | 전사 **안** 편집 가능 초안(제목·목록·체크리스트), 전체화면 | 없음 |
| Code block | CodeMirror급 편집·언어 라벨·Copy·Fullscreen·**Code/Preview** | HTML 카드 + copy 앵커만 |
| Preview | HTML/React/SVG/Mermaid/Vega를 **답 안**에서 | 없음 (diagram/app은 슬롯) |
| Run | 샌드박스 Python → 콘솔/출력을 블록에 | `project.run`은 IDE. 채팅 회수 계약 약함 |
| Apps | 인라인 iframe + display mode | App Host 슬롯만 |
| 풍부 레이아웃 | 브라우저 CSS, 호버, 카드 간격, KaTeX(시각+MathML) | Qt 부분집합 + 수식 PNG |
| 스트림 | 불완전 MD를 재파싱하며 레이아웃 안정 | 문자열 재렌더·타이핑. 파트 단위 아님 |
| Canvas | 현행 모델에서 축소. **인라인 블록**이 대체 | Iris에 사이드 Canvas 없음 → 목표도 인라인 블록 |

## 4. 구조

### 4.1 지금 (천장)

```text
Hermes/로컬 턴
  → content_chunk(str) / finished_ok(str)     ★ 본문 채널
  → (옆) app_ui(title, html_path, …)          ★ 앱 채널 (메시지 행과 분리)
  → DB content (str)                          ★ parts 없음
  → ChatPanel 스트림/타이핑 (str 버퍼)
  → ChatBlockBuffer로 prose/code/tool 절단 (저장 안 함)
  → render_iris_message / chat_blocks→HTML
  → _sanitize_chat_html
  → ChatLogTextEdit.insertHtml
       ├─ 표·코드카드·수식PNG·인용 칩  (가능한 것)
       └─ iframe/앱/편집기/Preview     (불가능 → 슬롯으로 도피)
```

### 4.2 목표 (GPT식 전사)

```text
턴 산출
  → MessageParts[]   ★ 정본 데이터
       text | writing | code | tool | image | app | citation | …
  → TranscriptHost   ★ QTextEdit 대체
       ├─ TextPart → 풍부 MD/HTML (브라우저급)
       ├─ WritingPart → 인라인 에디터 (편집 가능, 저장 시 content 갱신)
       ├─ CodePart → 에디터 + Preview/Run 탭
       ├─ AppPart → 샌드박스 iframe (인라인 / pip / fullscreen)
       └─ ToolPart → 접이식 셸
  → DB: content(표시용 평문 또는 MD 요약) + parts_json(정본)
  → 스트림: part open/delta/close 이벤트
```

갈라지는 지점 `★`가 두 개다. **데이터 형태**와 **호스트**. 둘 중 하나만 바꾸면 GPT 체감이 안 난다.

## 5. 코드 리뷰 (왜 지금 구조로는 안 되는지)

| 지점 | 하는 일 | GPT 목표를 막는 이유 |
|---|---|---|
| `ChatMessage.content` | 한 덩어리 문자열 | writing/code/app 상태를 보존·재개할 자리가 없음 |
| `render_iris_message` | MD→HTML | 파트 타입이 없음. Preview 탭·편집 상태를 표현 못 함 |
| `_sanitize_chat_html` | XSS 방어 | `iframe`/`style`/`svg` 제거 = 풍부 레이아웃·인라인 앱 금지 |
| `ChatLogTextEdit` | 단일 QTextDocument | 중첩 웹뷰·CodeMirror·ProseMirror를 문서 안에 못 심음 |
| `fenced_code_to_html` | 정적 HTML 카드 | Preview/Run/인라인 편집 없음 |
| `AppHostCard` | 로그 밖 슬롯 | 전사의 일부로 스크롤·히스토리 정렬이 안 됨 |
| `begin_stream_message` | str 청크 | part boundary·미완성 fence를 블록 위젯으로 고정하지 않음 |
| 2026-10-19 설계 C단계 보류 | 비용·안정성 | **목표를 GPT 패리티로 올리면 이 보류가 핵심 장애** |

### 하지 않은 일 (의도적 / 이전 범위)

- 채팅 로그 WebEngine 전면 교체
- 메시지 parts 스키마
- Writing block / Code Preview
- App Host를 버블(또는 턴 행) 안으로 이동

## 6. 수정 지도 (최소구현 아님)

원칙: **Experience First**로 목표 UX를 고정하고, **Redesign from First Principles**로 데이터·호스트를 처음부터 다시 잡으며, **Outcome-Oriented**로 QTextEdit 호환 레이어를 오래 끌지 않는다.

### 6.1 호스트 후보

| 옵션 | 요지 | 이점 | 비용·위험 |
|---|---|---|---|
| **H1. WebEngine 전사** | 대화 전체를 Chromium 문서. parts를 DOM으로 | GPT와 같은 CSS/iframe/에디터 임베드 가능 | Qt WebEngine 수명·GL·기동(`ensure_qt_webengine_ready`), 브리지·보안 CSP, 기존 TTS/드롭/슬롯 abort 계약 재배선 |
| **H2. 메시지 위젯 리스트** | 턴마다 `QWidget` 행. prose는 QLabel/작은 WebEngine, code/app은 자식 위젯 | 네이티브 스크롤·드롭 재사용 가능 | 가상화·긴 대화 성능, 스트림 중 레이아웃 떨림, 테마 일관성 |
| **H3. QTextEdit + 커스텀 object** | 문서에 위젯 앵커 | 겉보기 작은 diff | Qt에서 불안정·제한 많음. GPT 패리티에 **비추천** |

**권고 (조사 판단):** 목표는 H1 또는 H2. H3는 패리티 목표가 아닐 때만.  
데스크톱 Iris + 이미 WebEngine(브라우저·App Host·IDE)이 있으므로 **H1이 GPT 레이아웃·인라인 앱에 가장 가깝다.** Companion/드롭/frameless 계약을 지키려면 H2가 통제하기 쉬울 수 있다. 착수 전 H1/H2 **프로토타입 Bakeoff**가 맞다 (`Exhaust the Design Space`).

### 6.2 단계 (검증 가능한 단위)

각 단계는 「데모 한 턴이 GPT식 한 면을 보여 주는가」로 끝낸다. 중간 호환용으로 QTextEdit에 기능을 욱여넣지 않는다.

| 단계 | 산출 | 완료 기준 |
|---|---|---|
| **T0. 도메인** | `MessagePart` frozen types + serde + 「표시용 MD 요약」 | 단위 테스트로 round-trip. UI 없음 |
| **T1. 저장** | `chat_messages.parts_json` (또는 옆 테이블). 구 `content`는 fallback 요약 | 재시작 후 parts 복원 |
| **T2. 호스트 프로토타입** | H1 또는 H2로 빈 전사 + text part만 | 동일 샘플 MD가 브라우저급 타이포·여백으로 보임 |
| **T3. Code part** | 인라인 에디터 + Copy + **Preview**(HTML/SVG 최소) | 채팅 **안**에서 Preview 탭 전환 |
| **T4. Writing part** | 편집 가능 초안 + 저장이 parts·후속 컨텍스트에 반영 | 사용자가 고친 초안이 다음 턴에 쓰임 |
| **T5. App part 인라인** | 기존 App Host를 part로. displayMode | 계산기가 턴 행 안에 보임. 슬롯 기본 경로 제거 |
| **T6. 스트림** | part open/delta/close. 미완성 fence가 코드 블록으로 고정 | 스트림 중 레이아웃이 카드 단위로 안정 |
| **T7. Run/플롯** | code run → execution part / image part | GPT Run·플롯이 전사에 착지 |
| **T8. 모델 계약** | Hermes nudge / 도구가 parts 또는 fence 메타를 내게 | 자유 MD만으로 writing/app을 추론하지 않음 |

T0→T1이 **Foundational Thinking**의 데이터 형태다. T2 없이 T3를 QTextEdit에 올리면 다시 막힌다.

### 6.3 반드시 같이 움직이는 경계

| 층 | 변경 |
|---|---|
| 저장 | `conversations.append_message` / load / 사이드바 미리보기 |
| 워커 시그널 | delta를 str만이 아니라 part 이벤트로 (또는 최종 parts hydrate) |
| ChatPanel | `ChatLogTextEdit` 중심 API → Transcript API |
| TTS / message_regions / 복사 | 파트 단위 선택·읽기 |
| sanitize | 전사 CSP·iframe allowlist로 이동 (문서 HTML sanitize와 분리) |
| App Host / Diagram | 슬롯 → AppPart / DiagramPart |
| 착지 계약 | assistant 행 = parts 포함. 빈 HTML 앱은 part 검증 실패 |

### 6.4 이전 P0(matrix)와의 관계

P0 matrix·수식 PNG·플롯 PNG는 **text/image part 렌더러 안의 세부**로 흡수하면 된다.  
그것을 「GPT식 채팅창 완성」의 정의로 쓰지 않는다.

## 7. 차용

| 이름 | 가져올 부분 | 가져오지 않는 이유 |
|---|---|---|
| ChatGPT writing/code blocks UX | 인라인 블록, Preview/Run, 편집 후 대화 반영 | OpenAI 프론트 코드 없음. 동작 계약만 |
| CodeMirror / Monaco | code part 에디터 | 전사 호스트 결정 후 임베드 |
| KaTeX | 수식 시각+접근성 | 지금 PNG(`math_latex`)는 text part 폴백으로 유지 가능 |
| MCP Apps / Apps SDK | 인라인 iframe, displayMode, data/render 분리 | Iris SpeakTools와 병행. 위젯은 AppPart |
| Streamdown / 불완전 MD 스트림 파서 | 스트림 중 fence 안정화 | 파트 스트림과 함께 |
| Theia/WebEngine 기존 Iris 경로 | 프로세스 내 Chromium 운영 교훈 | 채팅 전사를 Theia로 만들지 않음 |

찾지 못함: QTextEdit만으로 GPT writing/code Preview와 동급을 내는 유지보수 가능한 패턴.

## 8. 위험

| 위험 | 완화 |
|---|---|
| WebEngine 채팅 = 0xC0000409 / GL | `ensure_qt_webengine_ready`, frameless·모달 부모 규칙, 단계별 자검 |
| 긴 대화 DOM 비대화 | GPT도 가상화 안 함(역설계). 우선 동일. 필요 시 윈도우 가상화 |
| XSS / 임의 HTML 앱 | AppPart CSP, 완성 HTML 게이트, remote 기본 차단 |
| 이중 정본 (MD vs parts) | parts가 정본. `content`는 검색·제목·폴백 요약만 |
| 마이그레이션 | 구 대화는 `content`→단일 text part로 hydrate |

## 9. 조치

1. 제품 목표를 「QTextEdit 개선」이 아니라 「typed parts + 전사 호스트 교체」로 고정한다.
2. H1 vs H2를 짧은 프로토타입으로 bakeoff한다 (동일 샘플: writing·code preview·인라인 계산기).
3. bakeoff 승자 기준으로 Feature multi-phase (T0–T8)를 연다.
4. 기존 App Host 빈 HTML 게이트(P0)는 T5 전까지 **임시 품질 가드**로만 둔다. 목표 아키텍처의 대체물이 아니다.
