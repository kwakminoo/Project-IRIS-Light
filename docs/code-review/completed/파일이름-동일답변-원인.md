# 파일 이름이 iris_generated.py이고 두 답이 같은 이유

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-CR-20261006-NAME |
| 작성일 | 2026-10-06 |
| 관련 | 대화 24, `chat_messages` 290–293, Hermes `agent.log` |
| 대상 | IDE 채팅에서 사진 속 코드를 `이미지테스트2`로 만들고, 이어서 그 이름으로 바꾸라는 요청 |
| 목적 | 같은 답과 다른 파일명이 말버릇인지, 앱이 그렇게 만든 것인지 가른다 |

## 1. 결론

모델이 같은 말을 두 번 한 것이 아니다. 모델 답은 693자와 731자로 달랐다. 화면과 DB에 남은 80자는 앱이 답 전체를 바꾼 고정 문장이다.

파일명 `iris_generated.py`는 사용자가 말한 이름을 읽지 않는 고정 규칙이다. 「구구단」이 아니면 그 이름이다. 이름 변경 요청은 도구를 타지 않았다. `이미지테스트2.py`는 없다.

## 2. 확인한 사실

출처: `%USERPROFILE%\.iris-light\iris_light.db`, Hermes `agent.log`, 작업 폴더 `컴퓨터비전`.

| 시각 | 쪽 | 저장 글 | 모델이 낸 길이 |
|---|---|---|---|
| 14:49:17 | 사용자 | 이미지테스트2를 만들고 사진 속 코드를 작성 | — |
| 14:49:27 | 비서 | IDE에 `…\컴퓨터비전\iris_generated.py` 파일을 열었습니다. | 693자, 도구 0회 |
| 14:50:21 | 사용자 | 이름을 이미지테스트2로 변경 | — |
| 14:50:29 | 비서 | 위와 같은 한 줄 | 731자, 도구 0회 |

모델은 `gemma4:31b-cloud`. 두 턴 모두 `tool_turns=0`, `reason=text_response`.

디스크:

| 파일 | 있음 | 시각 | 내용 |
|---|---|---|---|
| `iris_generated.py` | 있음 | 14:50:29 | `mistyroad.jpg` 명암 변환. 655바이트 |
| `이미지테스트.py` | 있음 | 14:34:33 | `soccer.jpg` 감마. 이번 요청과 다른 파일 |
| `이미지테스트2.py` | 없음 | — | — |

두 번째 사용자 말풍선에는 첨부 줄이 없다. 그래도 `model_content`와 `attachments.log` 14:50:21은 같은 PNG를 다시 읽었다. 모델은 이름만 바꾼 요청에도 그 사진을 다시 받았다.

## 3. 구조

```text
채팅 전송 (IDE 동반 창)
└─ 첨부가 있으면 추출 후 모델에 경로·발췌를 붙임
└─ 사진+작성 파이프 (열린 편집 파일이 정확히 1개일 때만 모델 전에 처리)
   └─ 이번 두 턴은 여기 안 걸림 → Hermes 호출
└─ 모델 스트림 (도구 없음)
   └─ 코드 펜스가 보이면 _feed_live_vibe_stream
      └─ default_generated_rel_path → iris_generated.py
└─ _on_chat_finished
   └─ _gate_chat_completion
      └─ settle_completion_claim
         └─ 완료 단어 + 그 파일이 디스크에 있음
            → 답 전체를 「IDE에 `절대경로` 파일을 열었습니다.」로 교체
```

갈라지는 곳: 사용자가 말한 파일명은 이 경로 어디에도 없다. 이름 변경은 `rename_file`로 가지 않고, 같은 쓰기 경로로 다시 들어온다.

## 4. 코드 리뷰

| 지점 | 이번 증상에서 한 일 | 요청을 막지 못한 이유 |
|---|---|---|
| `default_generated_rel_path` | 줄기를 `iris_generated`로 고정. 예외는 본문에 「구구단」이 있을 때 `gugudan` | 「이미지테스트2」를 파일명으로 읽지 않음 |
| `_live_vibe_open_target`, `_write_fenced_once` | 펜스 언어만 보고 그 상대 경로에 씀 | 모델이 `project.write_file`을 부르지 않아도 앱이 씀 |
| `settle_completion_claim` | 「작성했습니다·파일을 열었습니다·저장했습니다」 등이 있고 파일이 있으면 `reveal_line`만 반환 | 693자·731자 본문을 버림. 경로가 같으면 문장도 같음 |
| `_handle_image_code_pipe` | 열린 파일이 1개가 아니면 통과시키고 모델을 부름 | 새 파일명을 만들어 주지 않음. 없을 때 이름을 묻는 분기는 이번엔 안 탐 |
| `iris_ide_client.rename_file` | 호출되지 않음 | 채팅 턴의 컨트롤 액션으로 연결되어 있지 않음 |
| Hermes | 글을 내기만 함 | 파일명·이름 변경을 실행하지 않음 |

하지 않은 일: 채팅 제목 생성(응답 20자·11자)은 이 말풍선이 아니다. `이미지테스트.py`는 14:34에 다른 사진으로 생긴 파일이고, 이번 두 턴이 그 파일을 고치지 않았다.

## 5. 개선안

빈 자리는 두 곳이다.

1. 만들기 요청의 파일명을 경로로 쓰는 자리. 지금 후보는 `iris_generated`와 `gugudan`뿐이다.
2. 「이름으로 변경」을 `rename_file`에 넘기는 자리. 지금은 코드 펜스가 있으면 다시 `iris_generated.py`에 쓴다.
3. 완료 게이트가 답 전체를 한 줄로 바꾸는 자리. 경로 확인은 남기되, 모델이 이름 변경을 말한 본문까지 지우면 두 요청이 같아 보인다.

## 6. 차용

| 이름 | 가져올 부분 | 이번에 가져오지 않는 이유 |
|---|---|---|
| IRIS IDE 브리지 `renameFile` (`iris_ide_client.rename_file`) | 열린 작업 폴더 안에서 경로를 바꿈 | 이미 클라이언트에 있다. 채팅 턴이 안 부른다 |
| Cline식 완료 확인 | 도구·디스크가 있을 때만 성공 문장 | 이미 `settle_completion_claim`으로 들어와 있다. 이번엔 그 확인이 답 전체를 지웠다 |
| Aider | 사용자가 말한 경로에만 적용 | 제품은 설치하지 않는다. 파일명 추출만 비어 있다 |

## 7. 조치

1. 파일명 규칙과 이름 변경 연결은 이 문서의 빈 자리만 채운다. 이번 문서에서는 코드를 고치지 않았다.
2. 채팅에 보이는 한 줄만으로 모델이 같은 답을 했다고 보지 않는다. 길이는 Hermes 로그의 `response_len`이다.
