# 브라우저 명령이 실행되지 않던 원인

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-10-22 |
| 대상 | 내장 브라우저 + Hermes 도구 + 유튜브 재생 |
| 관찰 | AGENT CONNECTED, 네이버 열린 상태에서 「유튜브에서 노래 하나 아무거나 틀어줘」→ 모델이 재생 불가라고 답하고 페이지가 그대로 |

## 1. 결론

끊긴 지점은 브라우저 엔진이 아니라 **의도 → 도구 호출**이다.

`browser.search` / `BrowserSession.execute` / QWebEngine 드라이버는 이미 있다. Hermes가 켜져 있으면(`AGENT CONNECTED`) 로컬 가로채기를 건너뛰고 `gemma4:e2b`가 `iris_invoke`를 부르길 기다린다. 이 모델은 도구를 부르지 않고 「텍스트만 담당한다」고 답한다. 시스템 프롬프트만 바꿔도 도구는 호출되지 않는다.

TTS ERROR / GPT-SoVITS 참조 음성 누락은 **별 경로**다. 채팅 텍스트는 TTS 전에 그려지고, 브라우저 라우터는 TTS를 부르지 않는다.

수정: 확신 높은 실행 문장은 Hermes 여부와 무관하게 같은 `browser.*` 액션을 직접 호출한다. 성공은 영상 URL이 아니라 `video`의 재생 상태로 판정한다.

## 2. 확인한 사실

| 항목 | 값 |
|---|---|
| AGENT CONNECTED | Hermes gateway 연결. 브라우저 제어와 무관 |
| 내장 브라우저 | Qt WebEngine, 프로필 `~/.iris-light/browser-profile`, 쿠키 유지 |
| 기존 도구 | `browser.search {engine:youtube, play:true}` + JS `tryPlay` |
| `tryPlay` 구버그 | Promise를 기다리지 않고 `pending:true`를 성공으로 반환 |
| `hermes_owns_local_intents(True)` | IDE/위키/PDF 로컬 가로채기 생략. 브라우저 play도 여기에 묶여 있었음 |
| 시스템 Chrome 로그인 | 공유되지 않음. Chrome 136+ 기본 프로필 CDP 차단 |

픽스처·카탈로그·intent 자검은 통과. 웹엔진 스모크(로컬 HTML 이동+스크롤) 통과. 실기 유튜브·앱 재시작 후 로그인 유지·연결 끊김 UI는 아래 §검증.

## 3. 구조

```text
사용자 입력
└─ MainWindow._execute_user_turn_body
   ├─ _try_local_pinned_status
   ├─ _try_local_browser_control          ★ 이번 분기 (Hermes 켜져 있어도)
   │    └─ match_browser_intent
   │         ├─ None → 아래로 (일반 대화)
   │         └─ play|pause|resume|search|open
   │              └─ ControlSurface.invoke(browser.search|media|navigate)
   │                   └─ BrowserSession.execute
   │                        ├─ WebEnginePageDriver.navigate / click
   │                        ├─ tryPlay / tryPause (Promise 대기)
   │                        └─ snapshot.media.playing 없으면 ok=False
   │              └─ format_browser_reply → 채팅 (TTS 미호출)
   ├─ hermes_owns_local_intents?  → IDE/위키/PDF 로컬 생략
   └─ Hermes / 모델
        └─ iris_invoke browser.*  (소형은 여기까지 안 감)
```

이번 요청이 갈라지던 곳: `_try_local_browser_control`이 없어서 Hermes 갈래로만 갔다.

AGENT vs BROWSER: 상단 칩을 분리했다. AGENT=Hermes, BROWSER=내장 페이지 phase/playing.

## 4. 코드 리뷰

| 지점 | 이번 증상에서 한 일 | 막지 못한 이유 |
|---|---|---|
| `agent_local_gate` | Hermes면 로컬 실행 의도를 모델에 넘김 | 소형이 `iris_invoke`를 안 부름 |
| Hermes skill `iris-browser` | play 예시를 문서로만 제공 | 모델이 스킬을 안 따름 |
| `main_window._workspace_screen_context` | 브라우저 화면이면 도구 이름을 프롬프트에 넣음 | 프롬프트 ≠ 호출 |
| `openai_compat` / 연번 9 | Hermes 밖 tools 배관 없음 | 설계상 Hermes 필수. 이번 수정은 라우터로 우회 |
| `BrowserSession` Search play | 검색→클릭→tryPlay | `ok=True`를 페이지 도착만으로 줌. Promise 미대기 |
| `_bridge.js` tryPlay | `play()` Promise를 `ok:true, pending` | 자동재생 실패를 성공으로 위장 |
| `top_status_header` AGENT | Hermes 연결만 표시 | 브라우저 제어 가능으로 오해됨 |
| TTS `_tts_can_start` / `_on_chat_failed` | 참조 음성 없으면 TTS ERROR만 | 채팅·브라우저를 멈추지 않음 (유지) |
| `webengine_setup` 프로필 | 재시작 후 쿠키 유지 | 이미 있음. Chrome 프로필과 공유하지 않음 |

하지 않은 일: Playwright/Playwriter 실행, 시스템 Chrome 확장 설치, 동의·연령·광고 우회, 스피커 출력 주장, 모델 교체.

## 5. 개선안

구조의 빈 자리만.

1. **실행 라우터** — 확신 높은 문장만 `browser.*`로 보냄. 일반 대화는 None.
2. **재생 검증** — `media.playing`이 아니면 실패. 광고면 광고라고만 말함.
3. **상태 분리** — AGENT ≠ BROWSER.
4. **팝업** — `createWindow`를 같은 프로필 탭으로 수용.
5. **대상 식별** — snapshot `target_id=tab:N`.

## 6. 차용

| 이름 | 가져올 부분 | 이번에 가져오지 않는 이유 |
|---|---|---|
| [Playwriter](https://github.com/remorses/playwriter) | 사용자가 로그인한 **같은** 브라우저를 쓴다. 탭을 명시한다. localhost 기본, 무인증 원격 포트 금지. a11y 스냅샷+locator | 확장+`localhost:19988` CDP 릴레이 전체. Iris는 프로세스 안 QWebEngine이 같은 역할. 코드 미복사 |
| [Playwright extension](https://github.com/microsoft/playwright/tree/main/packages/extension) | 확장으로 실행 중 Chrome에 attach. 기본 프로필 `--remote-debugging-port`는 Chrome 136+ 차단 | Qt WebEngine에는 CDP 엔드포인트가 검증되지 않음 (architect 기각). 확장 설치를 사용자에게 요구하지 않음 |
| [Browser Use](https://github.com/browser-use/browser-use) | 액션 루프 + DOM/스냅샷 | 별도 Playwright Chromium. 두 번째 브라우저를 띄우지 않기로 한 v1과 충돌 |

라이선스: 아이디어만 참고. 소스 재사용 없음.

## 9. 남은 제한

- 내장 WebEngine ≠ 시스템 Chrome. 로그인은 Iris 브라우저에서 따로 한다.
- 동의·로그인·연령·캡차·자동재생 차단은 우회하지 않고 이유로 답한다.
- 소리가 실제로 나오는지는 확인하지 않는다.
- 라우터에 안 걸린 모호한 브라우저 요청은 여전히 모델 도구에 의존한다.
- 팝업은 새 탭으로 받지만, 렌더 프로세스 크래시 후 자동 복구는 없다.
