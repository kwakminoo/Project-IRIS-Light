| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-REV-2026-1011-01 |
| 작성일 | 2026-10-11 |
| 관련 | IRIS-IMPL-2026-1008-02 명세, IRIS-REV-2026-0930-02, IRIS-IMPL-2026-1008-01 |

대조한 완료 기준은 `다중채팅-동시작업-1단계-구현보고서.md` 4절이다. 검사는 `iris/ui/_check_conversation_switch_cancel.py`, `tests/test_user_turn_dispatcher.py`의 `test_two_sessions_run_and_third_waits`, `iris/runtime/session_write_lock.py`의 `_check` 본문이다. 2026-10-11에 그 검사를 다시 실행하지는 않았다.

---

## 1. 결론

1단계 완료 기준 7개 중 본 경로는 5개가 코드와 검사 본문에 맞다. 전환은 워커를 취소하지 않고, 숨은 채팅의 토큰은 화면 로그에 섞이지 않으며, 동시 실행은 2이고, 정지 버튼은 화면 슬롯만 취소하며, 이어하기 횟수는 대화 id마다 남는다.

기준 2·5·7은 본 경로 밖에 구멍이 있다. 첨부·자료 읽기·이전 대화 검색의 콜백은 슬롯 바인딩이 풀린 뒤 화면 채팅에 글을 붙인다. 쓰기 잠금은 프로젝트 전체와 위키 일부 액션만 막는다. 음성 정지는 화면 슬롯만 끊으면서 모든 대화의 대기열을 지운다.

모델 분리와 worktree는 이 단계의 미완료가 아니다. 명세가 2·3단계로 미룬 항목이다.

## 2. 구조

```text
완료 기준을 보는 경로
  전송 _on_user_text(session_id)
    └─ Dispatcher 동시 2
         └─ _execute_user_turn
              ├─ try: _bound_slot 설정, 게이트 begin, 동기 기록
              └─ finally: _bound_slot = None          ← 기준 2가 갈라지는 곳
                   콜백 _continue_user_turn / _with_past_chats / _launch_chat_turn
                        화면 위젯·화면 대화 id·창 전역 프롬프트
  전환 _on_conversation_selected → _load_conversation
    └─ request_cancel 없음                          ← 기준 1은 여기서 충족
         토큰은 *_for_turn 이 슬롯 소유로 분기       ← 기준 2의 스트림 구간만 충족
  정지 _on_chat_stop → _cancel_current_turn
    └─ _slot_now() 가 화면 슬롯                     ← 기준 4 충족
  음성 정지 _submit_voice_turn
    └─ clear_pending() 전체                         ← 기준 4·7이 갈라지는 곳
  쓰기 call_registered → write_lock_target
    └─ 표에 있는 액션만                             ← 기준 5가 갈라지는 곳
```

## 3. 코드 리뷰

| 기준 | 판정 | 근거 |
|---|---|---|
| 1. 전환이 진행 중 워커에 `request_cancel`을 호출하지 않는다 | 충족 | `_load_conversation`은 부분 응답을 `pending_partial`에 남기고 TTS만 멈춘다. 검사는 `worker.cancelled`가 거짓이다 |
| 2. 보이지 않는 채팅의 토큰이 보이는 채팅 화면에 섞이지 않는다 | 스트림만 충족 | `_on_content_chunk_for_turn`은 다른 대화의 토큰을 `pending_partial`에만 더한다. 검사는 `HIDDEN-TOKEN`이 화면 로그에 없는 것을 본다. `_continue_user_turn`은 사용자 말풍선을 `self._chat`에 붙인 뒤 `showing`을 본다 |
| 3. 동시 실행은 2까지다. 셋째는 기다리고, 진행 중 둘을 취소하지 않는다 | 충족 | `MAX_CONCURRENT = 2`. 디스패처 테스트가 A·B만 `turn_ready`이고 C는 `concurrent_cap`인 것을 본다 |
| 4. 한 채팅의 정지는 그 슬롯만 취소한다 | 버튼만 충족 | `_on_chat_stop`은 화면 슬롯의 워커만 `request_cancel`한다. 검사는 다른 슬롯 워커가 취소되지 않는 것을 본다. 음성 정지는 `clear_pending()`으로 모든 대기열을 비운다 |
| 5. 두 슬롯이 같은 프로젝트 파일·IDE·터미널을 동시에 쓰지 않는다. 서로 다른 위키 노트는 동시에 쓸 수 있다 | 표 안의 액션만 충족 | `SessionWriteLock`은 `project.write_file`, `project.write_image_code`, `project.rename_file`, `project.run`, `ide.edit`, `ide.save`, `ide.task`, `ide.debug`를 창에 하나로 막는다. 위키 쓰기 다섯 개는 상대 경로마다 막는다. 잠금 자체 검사는 `_check`에 있다 |
| 6. 채팅 A의 이어하기 횟수가 B의 상한에 더해지거나, 화면 전환만으로 0이 되지 않는다. 상한은 8이다 | 충족 | 이어하기 필드는 `SlotAttr`이다. 검사는 전환 후 A가 4, B가 1인 것을 본다. `CAP = 8` |
| 7. 음성 인식과 TTS는 화면에 있는 채팅만 따른다 | TTS와 입력 대상은 충족, 정지는 아님 | 전환 시 `_stop_tts_playback`. 복귀 시 `away_reply`를 `_speak_returned_reply`로 한 번 읽는다. 인식 제출은 화면 `conversation_id`를 쓴다. 인자의 `session_id`는 제출에 쓰이지 않는다 |

충족 경로에서 하지 않은 일. 모델 피커를 슬롯에 두기, `set_inference_model` 제거, worktree, 메일·캘린더를 이 맵에 흡수하기.

### 기준 2가 깨지는 호출

`_execute_user_turn`은 `try`에서 `_bound_slot`을 두고 `finally`에서 푼다. 그 안에 `worker.start()`만 하고 돌아오는 경로는 콜백이 나중에 돈다.

| 콜백 | 풀린 뒤에 하는 일 |
|---|---|
| 첨부 `prepared` → `_continue_user_turn` | 화면 채팅에 사용자 말풍선. `_record_history`는 바인딩이 없으면 화면 세션 |
| 자료 읽기 `_on_material_read_done` | 같은 기록 경로 |
| `_with_past_chats`의 `proceed` → `_launch_chat_turn` | `self._conversation_id`로 검색. `_pending_past_chats` 등 창 전역 필드에 증거를 넣고 그 내용으로 메시지를 조립 |

동기인 짧은 전송은 `finally` 전에 `_launch_chat_turn`까지 끝나서 이 구멍 밖이다. 첨부·자료·검색이 있는 전송이 구멍 안이다.

### 기준 5의 표 밖

잠금이 없는 쓰기. `wiki.move_notes`, `note.export_pdf`, `ide.open_folder`, `ide.open_file`, `project.create_scaffold`, `project.open_similar`, `ide.marketplace_install`, `ide.set_project_root`.

잠금이 있는 위키 경로는 `replace("\\", "/")`만 한다. `notes/a.md`와 `notes/../notes/a.md`는 다른 키다.

`write_holder`는 인자에 `conversation_id`가 없으면 스레드 id의 음수를 쓴다. 컨트롤 서피스는 `ThreadingHTTPServer`라 요청 스레드가 다르면 서로 대기한다. 같은 대화의 재진입 키로는 쓰이지 않는다.

`acquire_project` / `acquire_wiki`는 타임아웃이 없다. `call_registered`의 `finally`가 그 요청의 잠금을 푼다.

## 4. 보안

| 항목 | 내용 |
|---|---|
| 대화 섞임 | 비동기 이어짐이 화면 세션에 사용자 글과 모델 맥락을 기록할 수 있다. 뒤 채팅의 첨부 내용이 앞 채팅 프롬프트로 들어간다 |
| 프롬프트 공유 | `_pending_past_chats`, `_pending_wiki_notes`, `_pending_code_notes`, `_pending_web_evidence`가 창에 하나다. 채팅 둘의 검색 결과가 한 요청에 붙을 수 있다 |
| 모델·비밀 | `set_inference_model`은 게이트웨이 기본 모델을 덮고, 대상에 키가 있으면 헤르메스 설정에 `api_key`를 쓴다. 채팅 런 둘이 이 쓰기를 겹친다. 메일·캘린더 워커도 같은 호출을 한다 |
| 요청 모델 무력화 | `stream_chat`은 `provider` 없이 `model`만 보낸다. `resolve_request_model`은 광고 모델이 하나면 요청 모델을 그 이름으로 바꾼다 |
| 기억 범위 | `X-Hermes-Session-Id`를 보내지 않는다. 동시 런이 게이트웨이 기본 세션을 같이 쓴다 |
| 잠금 우회 | 정규화되지 않은 위키 경로와 표 밖 쓰기는 두 대화가 같은 파일을 같이 고친다 |
| 삭제 | `_on_conversation_deleted`는 DB에서 대화를 지우고 그 슬롯 워커를 취소하지 않는다. 워커는 끝난 글을 그 id에 `append_message`할 수 있다 |
| 종료 | 창을 닫을 때 `all_slots()`의 워커는 `request_cancel` 뒤 `wait(1500)`이다 |
| 대기 고착 | 잠금에 타임아웃이 없다. 쥔 요청이 반환되지 않으면 프로젝트 쓰기가 그 대화 밖에서 멈춘다 |

키 값을 이 문서에 적지 않는다. 채팅 경로가 설정 파일에 키를 다시 쓰지 않게 하는 일은 2단계다.

## 5. 개선안

1단계 잔여로 남는 빈 자리.

1. 콜백 진입 시 그 턴의 슬롯을 `_bound_slot`에 다시 둔다. 프롬프트 조각을 슬롯으로 옮긴다.
2. 위키 잠금 키를 정규화한다. `wiki.move_notes`, `note.export_pdf`, IDE가 폴더를 바꾸는 액션을 잠금 표에 넣는다.
3. 음성 정지는 그 대화의 대기만 지운다.
4. 대화 삭제는 그 슬롯만 취소한 뒤 DB를 지운다.

2단계로 넘기는 빈 자리. 슬롯이 모델을 기억하고, 채팅 워커가 `set_inference_model`을 호출하지 않으며, 요청에 `model`·`provider`·세션 헤더를 싣는 것.

3단계로 남기는 것. Git worktree. 자동 병합 없음.

## 6. 차용

| 이름 | 가져올 부분 | 1단계 분석에서 가져오지 않는 이유 |
|---|---|---|
| 기존 `*_for_turn` | 턴 id로 슬롯을 찾는 방식. 콜백이 같은 방식으로 `_bound_slot`을 다시 두면 된다 | 새 큐 라이브러리가 필요 없음 |
| `SessionWriteLock` | 이미 있는 표식. 경로 정규화는 `pathlib`으로 충분 | 샌드박스 디스크를 추가하지 않음 |
| 헤르메스 요청 단위 모델 | 2단계 명세가 가져간다 | 1단계 잔여(잠금·삭제·음성)와 한 변경으로 넣지 않음 |
| Git worktree | 없음 | 이 분석의 구멍은 폴더 사본으로 막히지 않음 |

추가 프레임워크는 찾지 않았다. 빈 자리는 아이리스가 이미 가진 슬롯과 잠금이 콜백·액션 표까지 닿지 않는 것이다.

## 7. 조치

1. 이 문서의 1단계 잔여를 2단계 구현과 한 묶음으로 고치지 않는다.
2. 2단계 명세는 바인딩과 요청 단위 모델만 담는다. 잠금 표 확대, 삭제 취소, 음성 대기열은 별도 수정이다.
3. 모델 작업을 시작하기 전에 설치본 `/v1/capabilities`를 확인한다.
