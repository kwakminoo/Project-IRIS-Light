# 헤르메스 GUI·에이전트·완료신호·채팅착지 일체화

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-CR-2026-11-10-CHAT-LAND |
| 작성일 | 2026-11-10 |
| 관련 | Hermes ON 채팅, InternalSidecar, 완료→DB 착지 |
| 대상 | Iris GUI + sidecar + 완료 이벤트 |
| 목적 | 정상 채팅(같은 conversation에 assistant 행) 복구 |

## 1. 결론

NVIDIA(`z-ai/glm-5.3-flash`) 라이브에서 Iris-native 착지가 통과했다. 사용자 행과 비서 행이 같은 `conversation_id`에 쌓이고, 측정 후 GUI가 1개로 남는다. 완료 신호는 Windows에서 stdout만으로 깨질 수 있어 UDP(및 파일 백업)로 호스트에 전달한다.

증거 (실측):
- `iris_native_land.json` — user 1188 / assistant 1189 / cid 311
- `nvidia_land_ok.json` — user 1190 / assistant 1191 / cid 313 / ~18.9s / GUI 1→1

경로: `recv udp` → `recv done` → `finished_ok` → `land_db_ok` (`landed_from: iris_native`)

## 2. 구조

요청이 갈라지는 경로:

```
chat.send (control HTTP)
  → MainWindow 턴 디스패치
  → HermesChatWorker (Hermes ON)
  → shared_engine().run_turn
  → sidecar stdin turn
  → Hermes run_conversation
  → Turn ended (agent.log)
  → sidecar emit done (UDP + 필요 시 terminal file)
  → Engine recv done
  → finished_ok
  → MainWindow DB/UI 착지
```

이번 증상이 갈라진 지점: sidecar가 답을 냈는데 호스트 stdout 수신이 깨지거나, 턴 전 native speak 프로브가 워커를 막아 Hermes 자체가 안 돌거나, 이중 GUI/sidecar가 파이프 짝을 어긋나게 함.

## 3. 코드 리뷰

| 지점 | 이번 증상에서 한 일 | 막지 못한 이유 |
|---|---|---|
| `HermesChatWorker._wire_native_speak_tools` | 매 턴 wiki/mail/calendar 동기 호출 | 핫패스에서 무한 대기에 가깝게 블로킹 → `hermes_end=null` |
| `gui_singleton` (msvcrt → CreateMutex Global) | 이중 GUI·이중 sidecar | venv pythonw 스텁+실GUI 카운트 혼선, Local 뮤텍스 경계 |
| `_sidecar_main` done emit | stdout만 사용 | Windows에서 done write/EINVAL로 호스트가 `recv done` 못 받음 |
| Turn ended → done | `run_conversation` return 대기 | Hermes #131740 wedge (Turn ended 후 return 지연) |
| `LiveActivityPanel.append_reasoning` | reasoning 슬롯 | 메서드 누락 → AttributeError → 0xC0000409 |

하지 않은 일: GUI와 Hermes를 단일 OS 프로세스로 합치기. 제품 “일체화”는 완료신호·착지 계약으로 맞춤.

## 4. 개선안

| 빈 자리 | 조치 |
|---|---|
| 채팅 핫패스 프로브 | `IRIS_WIRE_NATIVE_SPEAK_TOOLS` 기본 OFF |
| 단일 GUI | Global named mutex + 릴런치 시 실GUI만 카운트 |
| Turn ended wedge | 로그/스트림 기반 조기 done + grace |
| stdout 깨짐 | done/fail을 UDP로 전달, Engine이 recv |
| Qt abort | `append_reasoning` 복구, 슬롯 예외 차단 |

## 5. 차용

| 이름 | 가져올 부분 | 이번에 가져오지 않는 이유 |
|---|---|---|
| Hermes turn_liveness / #131740 | Turn ended↔return wedge 진단 | Iris sidecar 경계에서 단말 이벤트로 처리하면 충분 |
| Windows named mutex | 단일 인스턴스 | 이미 CreateMutex로 반영 |
| localhost UDP datagram | 깨진 stdout 우회 | 이미 Engine/sidecar에 반영 |

## 6. 조치

1. 재발 방지 규칙: `.cursor/rules/hermes-chat-landing.mdc` (alwaysApply).
2. 라이브 채팅은 thin launcher/`pythonw -m iris`로 최신 소스 사용.
3. 커밋·PR은 요청 시 진행.
