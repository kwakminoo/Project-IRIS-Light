# 다중 채팅 동시 작업 3단계 분석 보고서

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-REV-2026-1013-01 |
| 작성일 | 2026-10-13 |
| 관련 | IRIS-REV-2026-1012-02, `docs/prompts/다중채팅-동시작업-3단계-구현프롬프트.md`, IRIS-IMPL-2026-1008-01 |
| 대상 | Iris Light 3단계 작업 폴더 |
| 목적 | 3단계 완료 기준을 소스와 대조하고, 그 다음에 남은 일이 있는지 판단한다 |

대조 기준은 구현 프롬프트와 구현 보고서 3단계다. 2026-10-13에 `tests.test_chat_worktree` 2건과 `python -m iris.ui._check_turn_followup`이 통과했다. `python -m iris.ui._check_conversation_switch_cancel`은 `conversation switch keeps background run ok`를 찍은 뒤 창을 닫고, 프로세스가 `0xC0000005`로 끝났다. 검사 문장은 통과했다. 이 종료 코드는 작업 폴더 분리의 실패로 보지 않는다.

---

## 1. 결론

3단계로 적힌 일은 소스에 있다. 같은 저장소의 다음 대화는 `git worktree add`로 폴더를 나누고, 본 트리로 합치는 명령은 없다. 1·2·3단계 뒤에 적힌 다음 단계는 없다.

남은 일은 단계 하나가 아니다. 둘째 대화의 터미널은 이미 떠 있는 IDE 창을 그대로 쓸 수 있다. 주소·키 한 칸, 잠금 대기, 표 밖 IDE 액션은 세 단계가 맡지 않기로 한 자리다.

---

## 2. 구조

```text
프로젝트 루트 _current_project_root
  └─ work_root_for(대화 id, profile.project_root)
       ├─ git 아님 → 요청 경로
       ├─ 이 저장소의 첫 대화 → 그 체크아웃
       └─ 다음 대화 → git worktree add
            <저장소>.iris-worktrees/chat-<id>
            브랜치 iris/chat-<id>
                 ├─ project.write_file / rename_file / run / list_files
                 ├─ ide.open_folder / ide.enter_companion
                 └─ profile.project_root 는 사본 경로로 덮지 않음
project.run
  └─ 작업 폴더와 bound IDE workspace 가 다르면 거부     ← 터미널이 갈라지지 않는 곳
ide.enter_companion
  └─ 기존 bound 세션이 있으면 그 창의 workspace 를 유지
본 트리
  └─ project.worktree_status → describe_for_main
       └─ merged 는 항상 false. git merge 없음
```

갈라지는 지점은 폴더 계산이 끝난 뒤, 터미널이 창에 하나인 IDE 세션을 다시 쓰는 곳이다.

---

## 3. 코드 리뷰

| 기준 | 판정 | 근거 |
|---|---|---|
| 첫 대화는 본 체크아웃을 유지한다. 다음 대화는 `git worktree add`로 폴더를 만든다. git 이 아니면 경로를 유지한다 | 충족 | `work_root_for`. 검사 2건이 본 트리와 사본, 일반 폴더를 본다 |
| 쓰기·이름 변경·실행·목록·폴더 열기는 그 폴더를 본다 | 경로 계산은 충족 | `project.py` 네 곳과 `ide.open_folder`가 `work_root_for`를 탄다. 프롬프트의 프로젝트 루트는 `_current_project_root`다 |
| 사본 경로를 `profile.project_root`에 덮어쓰지 않는다 | 충족 | `is_chat_worktree`이면 `_open_ide_folder`, `_open_iris_ide_folder`, `ide.enter_companion`이 프로필을 저장하지 않는다 |
| 본 트리 병합이 없다. `confirm`이 있어도 본 트리 파일은 바뀌지 않는다 | 충족 | `describe_for_main`의 `merged`는 거짓이다. `chat_worktree.py`의 git 인자에 `merge`와 `cherry-pick`이 없다 |
| 위키 노트로 사본을 만들지 않는다 | 충족 | `note_opened`와 `note_file_written`이 `.iris-worktrees` 경로에서 반환한다 |
| 그 세션의 터미널만 그 폴더를 본다 | 폴더가 다를 때 실행은 거부 | `project.run`은 bound workspace와 다르면 오류를 반환한다. `_enter_ide_companion`은 기존 세션의 `workspace_root`를 유지한 채 돌아온다 |

충족 경로에서 하지 않은 일. 자동 병합, 자동 worktree 삭제, 헤르메스 소스, 세션 헤더, 잠금 타임아웃, 표 밖 IDE 액션을 잠금 표에 넣기. 작업 폴더 표는 `ChatRunSlot` 필드가 아니라 `chat_worktree` 모듈에 있다.

`worktree add`가 실패하면 그 호출은 요청 경로를 그대로 돌려준다. 프로세스를 다시 켜면 메모리 표는 비고, 디스크 폴더는 남는다. 프롬프트가 이 천장을 적었다.

---

## 4. 개선안

3단계 안에 남은 빈 자리.

1. 둘째 대화의 실행이 기존 IDE 세션의 폴더와 달라 거부되는 자리. 폴더 계산은 되어 있고, 그 창을 사본으로 바꾸지는 않는다.

3단계 밖에 남은 빈 자리. 게이트웨이 설정의 주소·키 한 칸. `acquire_project` / `acquire_wiki`의 대기 시간. `ide.open_file`, `ide.marketplace_install`, `ide.set_project_root`. 프로젝트 잠금은 폴더가 달라도 하나다. 이 자리는 새 단계로 적혀 있지 않다.

---

## 5. 차용

| 이름 | 가져올 부분 | 이 분석에서 가져오지 않는 이유 |
|---|---|---|
| `git worktree add` | 이미 다음 대화의 폴더 생성에 들어 있다 | 다시 넣지 않음 |
| 사용자 확인 뒤의 본 트리 반영 | `describe_for_main`은 경로만 돌려준다 | 병합 명령은 없음. 가져가기는 사용자가 한다 |
| 기존 bound IDE 세션 재사용 | 창이 하나일 때의 타일 | 사본 폴더로 그 창을 바꾸지 않음. 이번 빈 자리 |
| `X-Hermes-Session-Id` | 없음 | 본문 이전 턴을 `state.db`로 바꾸므로 넣지 않음 |
| 잠금 타임아웃·표 밖 IDE | 없음 | 3단계 프롬프트가 한 묶음으로 넣지 말라고 함 |

---

## 6. 조치

1. 1·2·3단계 다음에 새 단계를 열지 않는다.
2. 다음 수정이 있으면 기존 IDE 세션을 재사용한 채 `project.run`이 거부되는 자리부터 본다.
3. 주소·키 한 칸, 잠금 대기, 표 밖 IDE 액션은 그 수정과 한 묶음으로 넣지 않는다.
4. 본 트리 병합과 worktree 자동 삭제는 넣지 않는다.
