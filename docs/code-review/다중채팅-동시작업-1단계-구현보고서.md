# 다중 채팅 동시 작업 1단계 구현 보고서

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-IMPL-2026-1008-02 |
| 작성일 | 2026-10-08 |
| 관련 | IRIS-IMPL-2026-1008-01 의 1단계 |
| 대상 | Iris Light 메인 채팅 실행 |
| 목적 | 같은 모델로 채팅 둘의 루프를 동시에 두기 위한 1단계 명세 |

확인일 2026-10-08. 키보드 전송은 `MainWindow._on_user_text`에서 `UserTurnDispatcher.submit`으로 가고 `session_id`가 없다. 점유는 `ChatTurnGate.busy` 하나이고 `MainWindow._busy`가 그 값을 읽는다. 워커는 `_chat_worker` 하나다. 전환은 `_load_conversation`이 `busy`일 때 `_cancel_current_turn(reason="conversation_switch")`를 호출한다. 이어하기 상한은 `iris/runtime/turn_followthrough.py`의 `CAP = 8`이다.

---

## 1. 결론

1단계는 대화 id마다 실행을 나누고, 전환에서 취소를 빼는 일이다. 모델은 하나다. 원격 API는 그 모델로 요청을 여러 건 받는다. 동시 루프는 2로 시작한다. 쓰기는 잠금으로 한 채팅만 한다. 헤르메스 소스, `set_inference_model` 제거, Git worktree는 이 단계에 없다.

---

## 2. 구조

```text
보이는 채팅에서 전송
  └─ submit(대화 id = 지금 화면)
       └─ 그 id의 슬롯이 비었고 동시 수가 2 미만
            └─ 그 id의 워커·점유·이어하기
                 └─ 지금과 같은 Hermes 호출 (모델 전역 설정은 유지)
                      ├─ 토큰 → 그 대화 DB
                      └─ 화면 첨부 → id가 포그라운드일 때만
전환 _load_conversation
  └─ 기록과 구체만 교체
       └─ request_cancel 하지 않음          ← 1단계에서 끊는 가지
쓰기 도구
  └─ 잠금이 있으면 실행, 없으면 그 세션만 대기
```

위키 `projects/<슬러그>/chats/<대화 id>.md`는 끝난 글의 보관이다. 슬롯의 키가 아니다.

---

## 3. 코드 리뷰

| 지점 | 1단계에서 하는 일 | 1단계에서 하지 않는 일 |
|---|---|---|
| `MainWindow.__init__` | 대화 id → 슬롯 맵을 여기서 만든다 | 첫 전송 때 속성을 새로 만들지 않음. 슬롯 예외는 창을 죽인다 |
| `_on_user_text` | 지금 대화 id를 실어 그 슬롯으로 보낸다 | 창의 `busy` 하나로 다른 채팅 전송을 막지 않음 |
| `UserTurnDispatcher` | 활성 턴을 대화 id별로 둔다. 동시 2 | 대기열 하나를 병렬로 간주하지 않음 |
| `_load_conversation` | 화면 기록·구체를 포그라운드 슬롯에 맞춘다 | `conversation_switch` 취소, 백그라운드 이어하기 삭제 |
| `_chat_worker` | 맵의 값 | 단일 필드 유지 |
| 이어하기 | 횟수·목표·`CAP 8`을 슬롯에 둔다 | 상한 삭제, 숫자 변경 |
| `set_inference_model` | 그대로 둔다 | 요청 단위 모델 |
| `project.write_file`, IDE, 터미널 | 잠금 하나를 얻은 슬롯만 실행 | worktree, 자동 병합 |
| 위키 노트 쓰기 | 상대 경로 잠금. 다른 경로는 동시에 가능 | 위키 폴더 하나를 세션으로 묶기 |
| 구체 `AppState` | 포그라운드 슬롯이 생성이면 돌고, 아니면 쉰다 | 뒤 채팅이 산다고 포그라운드에서 돌리기 |
| 음성 | 아래 5절 규칙 | 마이크를 채팅마다 만들기 |

하지 않은 일. 2단계 모델 필드, 3단계 폴더 사본, 헤르메스 게이트웨이 분리, 메일·캘린더 패널을 이 맵의 본보기로 삼기. 그 패널은 나중에 흡수할 대상이다.

## 4. 1단계. 세션 실행

슬롯에 두는 것. 워커, 점유, 턴 id, 무시 플래그, 이어하기 횟수·목표·세대, 도구 성공 횟수, 아직 화면에 안 붙은 부분 응답.

결과. 채팅 A가 생성 중이어도 B로 옮기면 A는 계속 기록에 붙고, B는 전송할 수 있다. A로 돌아오면 A가 아직 생성이면 구체가 다시 돈다. 떠난 동안 끝났으면 글은 채워져 있고 구체는 쉰다.

완료 기준.

1. 전환이 진행 중 워커에 `request_cancel`을 호출하지 않는다.
2. 보이지 않는 채팅의 토큰이 보이는 채팅 화면에 섞이지 않는다.
3. 동시 실행은 2까지다. 셋째는 그 채팅에서 기다리고, 진행 중 둘을 취소하지 않는다.
4. 한 채팅의 정지는 그 슬롯만 취소한다.
5. 두 슬롯이 같은 프로젝트 파일·IDE·터미널을 동시에 쓰지 않는다. 서로 다른 위키 노트는 동시에 쓸 수 있다.
6. 채팅 A의 이어하기 횟수가 B의 상한에 더해지거나, 화면 전환만으로 0이 되지 않는다. 상한은 8이다.
7. 음성 인식과 TTS는 화면에 있는 채팅만 따른다.

### 화면과 음성

구체는 창에 하나다. 포그라운드가 생성이면 돈다. 포그라운드가 쉬면 쉰다. 뒤 루프는 그 표시와 상관없이 계속된다.

마이크도 TTS도 하나다. 인식 결과는 지금 화면에 있는 대화 id로만 들어간다. TTS는 그 채팅만 읽는다. 다른 채팅으로 옮기면 읽던 TTS는 멈춘다. 옮겨 간 채팅에, 자리를 비운 동안 끝난 새 답이 있으면 그 답을 한 번 읽는다. 보고 있지 않은 채팅이 끝났다고 TTS가 끼어들지 않는다.

### 잠금

잠금은 도구 복사본이 아니다. 「이 대상을 고치는 대화 id」를 먼저 집는 표식이다. 못 집으면 그 슬롯만 기다린다. 다른 슬롯의 읽기와 조사는 계속된다.

| 대상 | 잠금 |
|---|---|
| IDE, `project.write_file`, 터미널, 열린 프로젝트에서 도는 명령 | 창에 하나. 쥔 대화만 실행 |
| 위키 노트 | 상대 경로마다 하나. 다른 경로는 동시 |
| 같은 위키 노트 | 그 경로를 쥔 대화만 |
| 읽기, 검색, 조사 | 잠금 없음 |

### 모델과 이어하기

1단계 전제. 진행 중인 슬롯이 있을 때 모델 피커로 다른 모델을 고르지 않는다. 고르면 `set_inference_model`이 기본 모델을 덮어 다른 슬롯의 요청과 섞인다. 그 분리는 2단계다.

이어하기는 사용자 없이 같은 목표로 다음 턴을 넣는 횟수다. 슬롯마다 센다. `CAP` 8은 유지한다. 「67건 저장」처럼 도구 증거가 있으면 8 전에 멈춘다. 8에 닿으면 그 채팅에 상한 안내를 남긴다. 상한을 없애면 자동 턴이 멈춤 전까지 반복된다.

### 검사

`python -m iris.ui._check_conversation_switch_cancel`은 전환이 취소하던 계약을 본다. 1단계는 그 계약을 바꾼 뒤, 전환이 워커를 취소하지 않는 검사로 교체한다. 슬롯 맵은 생성자에서 만들어졌는지, 이어하기 횟수가 대화 id마다 다른지, 쓰기 잠금이 둘째 쓰기를 막는지 각 하나 이상의 검사로 고정한다. 고친 뒤 `python -m iris.ui._check_turn_followup`을 실행한다.

## 5. 개선안

1단계가 메우는 빈 자리는 실행 맵, 전환 시 취소 제거, 쓰기 잠금, 포그라운드에 붙은 구체·음성이다. 요청 단위 모델과 작업 폴더 사본은 비워 둔다.

## 6. 차용

| 이름 | 가져올 부분 | 1단계에서 가져오지 않는 이유 |
|---|---|---|
| 대화 id | 슬롯의 키. 기록은 그 id의 DB | 새 저장소를 만들지 않음 |
| 포그라운드 / 백그라운드 루프 | 화면은 하나만 그리고 루프는 최대 둘 | Cursor 서브에이전트 구현을 넣지 않음 |
| 경로 잠금 | 같은 파일·같은 노트는 한 대화 | 샌드박스 디스크를 새로 만들지 않음. 공유 폴더가 기본 |
| 헤르메스 동시 런 | 게이트웨이 하나가 런을 둘 받는 전제 | Sessions API·`provider` 필드 전환은 2단계 |
| Git worktree | 없음 | 코딩 병렬은 3단계 |

## 7. 조치

1. 이 문서의 슬롯 맵, 전환 취소 제거, 동시 2, 쓰기 잠금, 음성·구체 규칙만 구현한다.
2. `CAP` 8과 `set_inference_model`과 위키 보관 경로는 유지한다.
3. 2단계·3단계 코드는 넣지 않는다.
