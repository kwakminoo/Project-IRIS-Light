# 다중 채팅 동시 작업 2단계 구현 보고서

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-IMPL-2026-1011-01 |
| 작성일 | 2026-10-11 |
| 관련 | IRIS-REV-2026-1011-01, IRIS-IMPL-2026-1008-01, IRIS-REV-2026-0930-02 |
| 대상 | Iris Light 메인 채팅의 모델 호출과, 그 호출이 읽는 슬롯 바인딩 |
| 목적 | 채팅 둘의 모델이 게이트웨이 기본값을 덮어쓰지 않게 하는 구현 명세 |

전제. 1단계 슬롯, 동시 2, 전환 시 취소 제거, `CAP` 8, `SessionWriteLock`은 유지한다. 이 단계가 메우는 것은 분석 보고서의 「2단계로 넘기는 빈 자리」뿐이다. 잠금 표 확대, 대화 삭제 시 워커 취소, 음성 `clear_pending()` 범위는 이 문서의 구현 항목이 아니다.

2026-10-11 소스. `HermesChatWorker.run`이 `client.set_inference_model` 뒤에 `stream_chat`을 호출한다. `stream_chat` 페이로드는 `model`, `messages`, `stream`이다. `_headers`에는 세션 헤더가 없다. `resolve_request_model`은 광고 목록이 하나면 그 이름을 반환한다. `_execute_user_turn`은 `finally`에서 `_bound_slot`을 푼다. 모델 문자열은 `_execute_user_turn_body`가 `self._chat.current_model()`에서 읽는다.

---

## 1. 결론

2단계는 슬롯이 자기 모델을 기억하고, 채팅 스트림이 그 모델과 `provider`만으로 완료 API를 호출하게 하는 일이다. 비동기 콜백은 그 슬롯을 다시 묶은 뒤에 기록과 프롬프트를 읽는다. 헤르메스 소스와 게이트웨이 프로세스는 바꾸지 않는다.

착수 전에 설치본이 요청의 `provider`를 적용하는지 본다. 적용하지 않으면 구현을 멈추고 그 사실만 보고한다. `direct_model_requests`를 켜서 `set_inference_model`을 계속 호출하는 우회는 하지 않는다.

---

## 2. 구조

```text
전송 또는 이어하기
  └─ _execute_user_turn 이 대화 id의 슬롯을 묶음
       └─ 이번 사용자 턴이면 피커의 모델을 슬롯에 기록
       └─ 이어하기면 슬롯에 기록된 모델을 사용
            └─ 동기·비동기 공통
                 └─ 콜백 진입에서 owning(turn_id) 를 _bound_slot 로 다시 묶음
                      └─ 기록·프롬프트 조각은 그 슬롯
                           └─ HermesChatWorker
                                ├─ set_inference_model 호출 없음
                                └─ POST /v1/chat/completions
                                     model, provider, messages, stream
                                     X-Hermes-Session-Id = 대화 id
화면 피커·메일·캘린더의 기본 모델 동기화
  └─ 게이트웨이 기본값만 바꿀 수 있음
       └─ 이미 떠난 채팅 요청의 본문은 바꾸지 못함
```

갈라지는 지점은 슬롯에 모델을 쓰는 곳과, `stream_chat`이 `provider`를 싣는 곳이다. 피커를 바꿔도 진행 중 슬롯의 필드는 유지된다.

## 3. 코드 리뷰

| 지점 | 2단계에서 하는 일 | 2단계에서 하지 않는 일 |
|---|---|---|
| `ChatRunSlot` | 모델명과 provider(또는 이미 있는 `HermesInferenceTarget`에 해당하는 값)를 둔다. 생성자에서 빈 문자열로 만든다 | 슬롯 종류를 새로 나누지 않음 |
| `_execute_user_turn_body` | 사용자 턴은 화면 피커 값을 슬롯에 넣는다. 이어하기는 슬롯 값을 쓴다. 슬롯 값이 없으면 그 턴만 피커로 채운다 | 채팅마다 피커 UI를 만들지 않음 |
| `_execute_user_turn`의 `finally` | 함수 종료 시의 해제는 유지한다 | 콜백이 해제를 무시하고 화면 슬롯을 보게 두지 않음 |
| `_continue_user_turn`, `_on_material_read_done`, `_with_past_chats`의 `proceed`, `_launch_chat_turn` | 진입 시 `owning(turn.id)`로 `_bound_slot`을 다시 두고, 끝나면 푼다 | 검색용 대화 id로 `self._conversation_id`를 쓰지 않음 |
| 프롬프트 필드 | `_pending_past_chats`, `_pending_wiki_notes`, `_pending_code_notes`, `_pending_web_evidence`, 질문 종류를 슬롯으로 옮긴다 | 창 전역 필드를 남겨 두고 주석으로 막지 않음 |
| `HermesChatWorker.run` | 채팅 스트림 경로에서 `set_inference_model`을 호출하지 않는다 | 헤르메스 설정 파일에 `api_key`를 다시 쓰지 않음 |
| `stream_chat` | 인자로 받은 `model`과 `provider`를 페이로드에 넣는다. `X-Hermes-Session-Id`에 대화 id를 넣는다 | `provider`가 있는 요청을 `resolve_request_model`로 광고 이름 하나에 덮지 않음 |
| 메일·캘린더 워커 | 같은 `stream_chat`을 쓰면 그 요청도 `provider`를 싣는다. 기본 모델 동기화는 설정·피커 경로에만 둔다 | 메일 패널을 `ChatRunMap`에 흡수하지 않음 |
| 쓰기 잠금, 삭제, 음성 대기열, worktree, `CAP`, `MAX_CONCURRENT` | 유지 | 이 단계에서 고치지 않음 |

하지 않은 일. 헤르메스 저장소 수정, 게이트웨이를 프로세스 여러 개로 나누기, Sessions API로의 호출 교체, `session_model_pool`, `iris/core`.

`MainWindow`에 슬롯 필드를 추가하면 `__init__`의 `ChatRunMap` 생성과 `ChatRunSlot` 기본값이 그 속성을 만든다. 첫 콜백에서 속성을 새로 만들지 않는다.

## 4. 2단계. 요청 단위 모델

결과. 채팅 A가 모델 X로 생성 중일 때 B에서 모델 Y를 고르고 전송해도, A의 진행 중 요청과 이어하기는 X다. B의 요청은 Y다. A의 첨부·자료·이전 대화 검색이 늦게 끝나도 기록과 프롬프트는 A의 대화에만 붙는다. 화면에는 A의 토큰이 섞이지 않는다.

완료 기준.

1. 메인 채팅 `HermesChatWorker.run`이 `set_inference_model`을 호출하지 않는다.
2. 완료 요청 페이로드에 그 슬롯의 `model`과 `provider`가 있다. 광고 모델이 하나여도 `provider`가 있으면 슬롯 모델명을 유지한다.
3. `X-Hermes-Session-Id`는 그 대화 id다. 헤더 값은 latin-1로 인코딩되는 십진수다.
4. 슬롯 A의 이어하기는 A에 저장된 모델을 쓴다. 화면 피커를 바꿔도 A의 저장값은 바뀌지 않는다.
5. 첨부·자료 읽기·이전 대화 검색 콜백은 화면을 옮긴 뒤에도 그 턴의 대화 DB에만 사용자 글을 쓴다. 화면 로그에 그 글이 나타나지 않는다.
6. 두 슬롯의 `_pending_past_chats`에 해당하는 값이 한 요청에 합쳐지지 않는다.
7. `CAP`은 8, 동시 루프는 2, 전환은 워커를 취소하지 않는다.

### 착수 전 확인

설치본 게이트웨이에서 `/v1/capabilities`와 `gateway.api_server.max_concurrent_runs`를 읽는다. 문서 기본 동시 실행은 10이고, 넘으면 HTTP 429다. 아이리스 동시 2는 그 안이다.

요청 필드 우선순위는 공개 문서(2026-10-08, `api-server.md` 커밋 `a28a5d03`) 기준이다. 세션 덮어쓰기 → 라우트 별칭 → 요청의 `model`·`provider` → 전역 기본. `provider`가 있으면 그 요청의 모델이 적용된다. 설치본이 이 필드를 무시하면 코드를 넣지 않고 보고한다.

### 키

`set_inference_model`이 채팅 런마다 설정 파일에 `api_key`를 쓰던 경로는 채팅 워커에서 끊긴다. 페이로드와 로그와 활동 줄에 키 문자열을 넣지 않는다. 설정 화면이 기본 모델을 맞출 때의 기존 쓰기만 남을 수 있다. 그 쓰기는 이미 전송된 채팅 본문을 바꾸지 못한다.

### 검사

하나씩 둔다.

1. 슬롯 둘에 모델을 다르게 넣고, 채팅 워커 더블이 `set_inference_model`을 세지 않으며, `stream_chat`에 넘긴 `model`·`provider`·세션 헤더가 슬롯과 같다.
2. `provider`가 있을 때 `resolve_request_model`이 광고 이름 하나로 바꾸지 않는다.
3. 첨부 또는 이전 대화 검색이 비동기인 턴에서 화면 대화를 바꾼 뒤, 사용자 글이 원래 대화 DB에만 있고 화면 로그에는 없다.
4. 이어하기 제출이 슬롯에 저장된 모델을 쓰고 피커 값을 다시 읽지 않는다.
5. 기존 `python -m iris.ui._check_conversation_switch_cancel`과 `python -m iris.ui._check_turn_followup`이 통과한다.

---

## 5. 개선안

이 단계의 빈 자리는 둘이다.

1. 턴 콜백이 슬롯 바인딩과 프롬프트 조각을 그 대화에만 두게 하는 자리.
2. 완료 API 한 요청이 `model`, `provider`, 대화 id 헤더를 갖게 하는 자리. 기본 모델 쓰기는 그 요청 밖에 둔다.

잠금 표, 삭제 취소, 음성 대기열, worktree는 비워 둔다.

## 6. 차용

| 이름 | 가져올 부분 | 이 단계에서 가져오지 않는 이유 |
|---|---|---|
| 헤르메스 Per-request model selection | 완료 요청의 `model`과 `provider` | 게이트웨이 소스를 수정하지 않음. `direct_model_requests`로 전역 쓰기를 유지하지 않음 |
| `X-Hermes-Session-Id` | 기록 범위 헤더. 값은 대화 id | `POST /api/sessions`로 호출 경로를 바꾸지 않음. `X-Hermes-Session-Key` 장기 기억 분리는 넣지 않음 |
| 기존 `ChatRunSlot`과 `*_for_turn` | 모델을 슬롯에 두고, 콜백이 턴 id로 슬롯을 다시 묶음 | 디스패처를 교체하지 않음 |
| `session_model_pool` (hermes-agent#37519) | 없음 | 설치본 기능에 의존하지 않음 |
| Git worktree | 없음 | 모델 분리와 무관 |
| 다른 에이전트 SDK | 없음 | 호출 형식만 바꾸면 됨 |

## 7. 조치

1. 설치본 능력 확인이 끝난 뒤에만 이 문서의 슬롯 모델, 콜백 재바인딩, `stream_chat`의 `provider`·세션 헤더를 구현한다.
2. 채팅 워커의 `set_inference_model` 호출을 제거한다. 키는 로그에 남기지 않는다.
3. `CAP` 8, 동시 2, 전환 시 취소 금지, 쓰기 잠금 동작을 유지한다.
4. 1단계 잔여인 잠금 표, 대화 삭제, 음성 대기열과 3단계 worktree는 넣지 않는다.
