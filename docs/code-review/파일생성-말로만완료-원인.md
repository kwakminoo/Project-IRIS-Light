# 파일 생성 「말로만 완료」 — 원인과 개선안

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-CR-2026-10-27-WRITE-CLAIM |
| 작성일 | 2026-10-27 |
| 관련 | IDE-커서처럼-조작-현황, hermes_memory_nudge, file_write_claim, turn_followthrough |
| 대상 | Hermes 켜진 채팅에서 「스크립트 생성」 후 구조창에 파일이 없는 증상 |
| 목적 | 원인이 도구 미호출인지, 쓰기 실패인지 가른다. 개선 순서를 고정한다 |

## 1. 결론

디스크·IDE에 파일이 없는 직접 원인은 Iris 쓰기 API 고장이 아니다.  
Hermes 모델이 `mcp__iris_control__iris_invoke`(action=`project.write_file`)를 **호출하지 않은 채** 「생성했다 / 지금 생성한다」 문장만 내보냈다.

구체의 회전은 `_busy`·생성 중 상태와 묶인다. 도구 왕복이 없으면 턴이 바로 끝나고 구체는 돌지 않는다.  
「생성한다고 했는데 구체가 안 돈다」는 관측은 **쓰기 시도가 없었다**는 쪽과 맞다.

로컬 안전망도 의도적으로 꺼져 있다. 채팅 완료 문장만으로는 파일을 만들지 않는다.

| Hermes 실제 도구 이름은 `iris_invoke` | `hermes_memory_nudge.py` 규칙 1 | measured |

## 3. 구조

요청이 파일까지 가는 정상 경로와, 이번처럼 갈라진 경로.

```
사용자 「스크립트 생성해줘」
  → MainWindow 턴 시작 (_busy=True, 구체 활성)
  → Hermes 에이전트 루프
        ├─ [정상] mcp__iris_control__iris_invoke
        │         action=project.write_file
        │         → Control Surface → project_write_file
        │         → 디스크 + (open=true면) IDE 탭
        │         → _note_tool_file_write
        │
        └─ [이번 증상] 도구 호출 없음
                  → 최종 텍스트만 「생성했습니다」
                  → _gate_chat_completion (통과)
                  → settle 계열 (통과 / 미개입)
                  → _try_reveal_local_vibe_code (프롬프트 비어 return)
                  → _busy=False, 구체 정지
                  → 구조창 변화 없음
```

갈림은 Hermes가 tool_call을 내기 전이다.  
IDE 탐색기 새로고침·브리지 `createFile`은 그 갈림 이후에만 등장한다.

## 4. 코드 리뷰

| 지점 | 이번 증상에서 한 일 | 요청을 막지 못한 이유 |
|---|---|---|
| `hermes_memory_nudge` 규칙 12 | 쓰려면 `project.write_file` 쓰라고 안내 | 실제 MCP 이름은 `iris_invoke`. 모델이 액션 이름을 Cursor식 「도구」로 착각하고 말로만 완료하기 쉬움 |
| 규칙 19·22 | 도구 없을 때 발명 금지, 실패 시 허위 주장 금지 | 「파일 생성 완료」에 대한 동일 강도의 금지·강제 재시도가 약함 |
| `_handle_image_code_pipe` | 항상 False | 이미지 실습 코드도 Hermes에만 맡김 |
| `_pending_local_vibe_prompt` 비움 | 펜스→파일 폴백 차단 | 채팅에 코드를 붙여도 디스크에 안 씀 (설계) |
| `settle_completion_claim` | 표시 문장 유지 | 허위 완료를 고치거나 막지 않음 (설계·자검이 고정) |
| `_gate_chat_completion` | 입력 그대로 반환 | 완료 주장 검증 없음 |
| `decide_followthrough` | 위키 「저장했」+ tool_ok=0 이면 continue | 「생성했」「작성했」+ 파일 목표에는 재시도 없음 |
| `project_write_file` | (호출되면) root·바인딩 IDE 검사 후 기록 | 이번엔 호출 자체가 없어 여기까지 안 감 |

하지 않은 일 (증상과 무관하거나 2차).

- IRIS IDE 탐색기 폴러 버그로 파일이 숨겨진 경우. 쓰기 자체가 없으면 해당 없음.
- `project_root` ≠ bound workspace 거절. 도구 호출 로그가 있을 때만 2차 후보.

2차 (도구가 **실제로** ok였는데도 구조 트리만 비는 경우).

- IRIS IDE `createFile`은 Theia `FileService`가 아니라 브리지 Node `fs.writeFileSync`다. 탐색기 refresh API가 없다. 탭은 `openFile`로 열려도 구조 트리가 안 갱신될 수 있다. ([Explore IDE open-tab path](8bc41c3d-630e-4a81-ae42-d286a7a26b26))
- 이번 사용자 증상은 「생성한다」말 + 구체 미회전이라 1차(미호출)가 맞다. 탭도 없이 트리만 비면 2차를 본다.

## 5. 개선안

빈 자리만. 구현 순서는 위가 먼저.

| 순위 | 빈 자리 | 제안 | 완료 기준 |
|---|---|---|---|
| 1 | 허위 완료가 채팅에 그대로 남음 | 턴 종료 시 「생성/작성/저장했」류 + 이번 턴 `project.write_file`/`_note_tool_file_write` 없음이면 표시를 `CHAT_ONLY`로 바꾸거나 한 줄 정정. `_gate_chat_completion` 또는 `settle_completion_claim` 복원 | 자검. 도구 없는 「생성했습니다」가 성공 문장으로 안 남음 |
| 2 | 파일 목표에 followthrough 없음 | `decide_followthrough`에 스크립트/파일 생성 목표 + claim_ok=0 + 완료 주장 → `continue` (위키와 동일 패턴). CAP 유지 | 「생성해줘」→ 완료 문장만 → 자동으로 도구 재요청 1회 이상 |
| 3 | 넛지 이름 혼동 | 규칙 12를 `iris_invoke` → action=`project.write_file` 전체 경로로만 적기. 「ok 없이 생성했다고 말하지 말 것」을 파일에도 명시 | 넛지 버전 bump + MEMORY 재동기 |
| 4 | UI 증거 부재 | 도구 호출/ok 줄을 채팅·활동 로그에 항상 보이게. 구체는 tool round-trip 중에만 강조 | 사용자가 「도구 0회」를 바로 판별 |
| 5 | (선택) Hermes 의존 완화 | 「N개 스크립트 파일로 써」의도 + 본문에 코드가 이미 있으면 Iris가 `project.write_file`을 직접 호출 | Hermes 끄거나 모델이 무시해도 디스크에 생김 |
| 6 | (2차) 탐색기 stale | `createFile` 성공 후 Theia navigator refresh 또는 FileService 경로로 쓰기 | 탭은 있는데 구조창만 비는 재현이 있을 때 |

하지 말 것.

- 채팅 펜스만 보고 무조건 쓰기 폴백을 전면 복구. 예전에 IDE 연출·중복 개방과 충돌했음.
- `project.write_file` 핸들러만 손보기. 이번 1차 원인은 미호출.
