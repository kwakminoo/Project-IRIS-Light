# 모델 정리 기능 코드 리뷰 · 보안점

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-CR-MODEL-CLEANUP-2026-11-12 |
| 작성일 | 2026-11-12 |
| 관련 | NVIDIA EOL(`moonshotai/kimi-k3` HTTP 410) 선택 루프 수정과 동일 경로 |
| 대상 | AI Hub 「모델 정리」·선택 시 1회 실측·프로브 캐시 |
| 목적 | 구조·리뷰·개선안·차용을 남기고, 보안·남용 지점을 고정한다 |

## 1. 결론

모델 정리는 「이름 추정」을 버리고 HTTP 실측 결과를 DB에 캐시하는 구조다. 키는 DPAPI로 저장되고 목록·대화 프로브로 능력이 갈린다. 보안 구멍은 키 유출보다 **임의 Base URL로의 SSRF성 요청**, **프로브가 iris_chat으로 과대분류하는 점**, **EOL/unavailable 재검증 루프(수정됨)** 쪽이다.

## 2. 확인한 사실

| 사실 | 근거 |
|---|---|
| `kimi-k3` 선택 시 HTTP 410 + `no longer available` | 사용자 메시지. `state_from_http`/`model_is_gone`으로 `unavailable` |
| unavailable 후 `_refresh_models` → 재선택 → 재검증 루프 | `main_window._on_api_model_verified` → `_verify_api_model_once`가 ok만 스킵 |
| 로컬 Iris DB NVIDIA 제공자 81모델 중 `ok`+`tools=yes`는 6개 | `%USERPROFILE%\.iris-light\iris_light.db` 실측 (2026-11-12) |
| API 키는 `api_key_enc` + DPAPI/`local:` | `api_providers.py` + `secret_store.py` |
| `urlopen`에 스킴·호스트 제한 없음 | `openai_compat_client._http_json` |

## 3. 구조

요청이 지나가는 경로:

```
[AI Hub] 「모델 정리」
  → ApiModelsVerifyWorker
  → verify_model(base_url, api_key, model)
  → chat_smoke(+tools) / 실패 시 state_from_http
  → record_model_probe → SQLite providers JSON
  → 피커/카탈로그 (model_list_tier / fitness_for_probe)

[채팅 콤보] 모델 선택
  → _apply_selected_model
  → _verify_api_model_once   ← 여기가 갈림
       · should_skip_api_model_verify(unavailable|ok+tool) → 종료
       · 아니면 ApiModelVerifyWorker → _on_api_model_verified
            · unavailable → 안내 메시지 + _refresh_models
            · ok → 도구 미지원만 Live Activity
```

이번 EOL 증상은 `_verify_api_model_once` 갈림에서 `unavailable`을 스킵하지 못해, refresh가 다시 선택을 일으키며 루프가 난 것이다.

## 4. 코드 리뷰

| 지점 | 이번 증상에서 한 일 | 막지 못한 이유 / 보안 관찰 |
|---|---|---|
| `verify_model` | 410 본문을 unavailable로 분류 | 분류는 맞음. 루프는 UI 캐시 스킵 부재 |
| `_verify_api_model_once` | 재프로브 게이트 | ok+tool만 스킵 → unavailable 재호출 |
| `_on_api_model_verified` | 안내 후 `_refresh_models` | 의도(목록 라벨 갱신)는 맞으나 게이트와 결합되면 루프 |
| `usable_models` | unavailable도 이름 유지 | 제품 의도. 스킵 없으면 선택 가능 → 재검증 |
| `fitness_for_probe` | ok+tools=yes → `iris_chat` | 작업 적합성 없음. 전용 모델도 통과 가능 |
| `openai_compat_client` | 사용자 Base URL로 GET/POST | SSRF·메타데이터 엔드포인트 위험 (로컬 앱 한도) |
| `secret_store` | DPAPI 암호화 | Windows 사용자 컨텍스트 유출 시 복호화 가능. `local:` XOR는 약함 |
| `ApiModelsVerifyWorker` | 전 모델 순차 스모크 | 대량 호출·쿼터 소진·로그에 키/URL 노출 위험 |

## 5. 개선안

구조에서 빈 자리만:

1. **재검증 게이트** — `unavailable`은 영구 스킵(이번 수정). 수동 「모델 정리」만 재프로브.
2. **SSRF 경계** — 등록 Base URL을 `https:`(및 명시적 로컬 개발용 `http://127.0.0.1`)로 제한. `file:`·링크로컬·클라우드 메타데이터 IP 거절.
3. **적합도 ≠ 도구 성공** — `iris_chat`에 모달리티/용도 메타(또는 거부 목록)를 두어 safety/embed/calibration을 제외.
4. **EOL 일괄 처리** — 410을 받은 모델을 선택 중이면 다음 usable로 한 번만 이동(선택 사항).
5. **프로브 예산** — 제공자당 동시성·일일 상한. 실패 본문에서 키 마스킹.

## 6. 차용

| 이름 | 가져올 부분 | 이번에 가져오지 않는 이유 |
|---|---|---|
| OWASP SSRF 방어 패턴 | URL allow/deny, 사설 IP 차단 | 이번 픽스는 루프 차단만. SSRF는 별 PR |
| OpenAI SDK retry/status 매핑 | 410 Gone을 단말 상태로 | 이미 `state_from_http`로 충분 |
| LiteLLM model list | 벤더별 능력 메타 | Iris는 실측 우선 정책. 휴리스틱 재도입 금지 |
| 찾지 못함 | EOL 카탈로그를 자동 구독하는 오픈소스 훅 | NVIDIA 계정 목록 + 410이 사실상 소스 |

## 7. 조치

1. EOL 재검증 루프 수정 PR 병합.
2. SSRF·적합도 오분류는 후속 이슈로 분리.
3. NVIDIA 권장 모델은 Iris DB 실측표 기준으로 사용자에게 안내.
