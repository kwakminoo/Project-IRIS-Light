# 채팅 GPT식 표현 — PyQt6 유지 여부

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-CR-20261117-QTSTACK |
| 작성일 | 2026-11-17 |
| 관련 | `채팅-GPT식전사-목표아키텍처-2026-11-17.md`, `docs/guides/ui-toolkit-migration.md` |
| 대상 | GPT식 전사(인라인 블록·풍부 레이아웃·앱)를 위해 UI 언어/툴킷을 바꿔야 하는가 |
| 목적 | PyQt6 폐기 vs 유지 + 호스트만 교체의 판단 고정 |

## 1. 결론

**다른 언어로 UI를 갈아탈 필요는 없다.**  
막히는 것은 PyQt6 전체가 아니라 **채팅 로그의 `QTextEdit` 한 표면**이다.

GPT식 목표는 PyQt6 안에서 이미 쓰는 **`QWebEngineView` + `QWebChannel`**(또는 메시지 `QWidget` 리스트)로 전사 호스트만 바꾸면 도달 가능하다.  
Electron / Tauri / Flutter / 웹 전면 재작성은 능력상 이득보다 Iris 계약 재배선 비용이 크다.

| 선택 | 판단 |
|---|---|
| PyQt6 유지 + 전사 호스트 교체 (H1/H2) | **채택** |
| QTextEdit 그대로 sanitize만 확장 | **불가** (목표 대비) |
| PySide6로만 교체 | GPT 능력과 **무관** (라이선스 이슈용) |
| Electron/Tauri 등 비Qt 전면 | **비권장** (재작성·Companion/드롭/슬롯 abort 계약) |

## 2. 확인한 사실

| 사실 | 근거 |
|---|---|
| 채팅 답은 지금 `QTextEdit` HTML | `ChatLogTextEdit`, `render_iris_message` |
| Iris는 이미 Chromium을 프로세스 안에 씀 | 브라우저, App Host, IRIS IDE Theia |
| App Host가 `QWebEngineView` + WebChannel (`irisHost`) | `app_host_card.py` |
| 기동 시 `ensure_qt_webengine_ready()` | `iris/__main__.py` |
| PyQt6→PySide6 가이드는 라이선스용. GPT 패리티 목적이 아님 | `ui-toolkit-migration.md` |
| Web UI를 PyQt6에 심는 표준 경로 | Qt `QWebChannel`, PyQt6-WebEngine |
| 웹 쪽 writing/code는 ProseMirror+CodeMirror 등이 Chromium 위에 동작 | GPT Web 역설계·ProseMirror 예제. 언어가 Python일 필요 없음 |

## 3. 구조

```text
제품 셸 (창·타일·드롭·슬롯·Companion)     ← PyQt6 유지가 유리
        │
        ├─ Composer / 사이드바 / Live Activity  ← Qt 위젯 유지 가능
        │
        └─ 채팅 전사 (오늘: QTextEdit)         ← ★ 여기만 교체
                 │
                 ├─ H1: QWebEngineView 한 장 + JS 전사 (parts → DOM)
                 │         CodeMirror / Preview iframe / App iframe
                 │         Python ↔ JS = QWebChannel (App Host와 동일 패턴)
                 │
                 └─ H2: QScrollArea + 턴별 QWidget
                           prose / code WebView / app WebView 자식
```

막히는 층과 유지할 층을 섞지 않는다.

## 4. 코드·제품 리뷰

| 전제 | 맞는지 | 설명 |
|---|---|---|
| 「PyQt6라서 GPT식이 불가능」 | **틀림** | Chromium 임베드가 이미 있음. GPT 프론트도 결국 웹 런타임 |
| 「QTextEdit만으로 충분」 | **틀림** | iframe/style/편집기 천장. 이전 전사 보고서와 동일 |
| 「스택을 바꾸면 빠르다」 | **대체로 틀림** | `iris/ui` PyQt import ~100파일대. Companion 80:20, OLE DnD, frameless, `0xC0000409`, Hermes 착지, thin launcher가 Qt 가정 |
| 「PySide6면 해결」 | **아님** | 같은 Qt. QTextEdit 천장은 동일 |

### 대안 스택 한 줄

| 스택 | GPT식 전사 | Iris 비용 |
|---|---|---|
| PyQt6 + WebEngine 전사 | 가능 | 채팅 호스트·브리지만. 셸 계약 유지 |
| PyQt6 + 위젯 리스트 | 가능(레이아웃은 H1보다 손) | 네이티브 드롭과 친함 |
| PySide6 | 능력 동일 | 라이선스용. GPT와 무관 |
| Electron / Tauri | 웹 전사 쉬움 | 셸·Companion·Win32 타일·기존 UI 전면 재작성 |
| Flutter / SwiftUI 등 | 별도 설계 | Iris Python/Hermes/Qt 생태계와 단절 |

## 5. 개선안 (이 질문 범위)

1. **언어/툴킷은 PyQt6 유지.**
2. **「이대로」= QTextEdit 유지가 아니라, typed parts + H1/H2 호스트 교체로 진행.**
3. 채팅 전사 JS(또는 위젯)만 웹 스택을 쓰고, 창·에이전트·저장은 Python/Qt.
4. PySide6·Electron은 GPT 패리티 로드맵에 넣지 않는다. 라이선스/배포가 따로 필요해질 때만.

## 6. 차용

| 이름 | 가져올 부분 | 가져오지 않는 이유 |
|---|---|---|
| 기존 `AppHostCard` WebChannel | 브리지·보안 설정 패턴 | 슬롯 배치 자체는 전사 안으로 옮김 |
| ProseMirror + CodeMirror | writing/code 블록 UX | Electron 셸은 안 씀. WebEngine 페이지 안에만 |
| Qt QWebChannel 문서 | Python↔JS API | 새 프로토콜 발명 금지 |
| `ui-toolkit-migration` PySide6 | — | GPT 목표와 무관. 가이드만 유지 |

## 7. 조치

1. 판단 고정: **PyQt6 유지. QTextEdit 전사만 폐기(또는 부속).**
2. 다음 작업은 언어 전환 조사가 아니라 H1/H2 bakeoff + `MessagePart` T0.
3. 「스택 교체」제안이 다시 나오면 이 문서의 표로 거절한다.
