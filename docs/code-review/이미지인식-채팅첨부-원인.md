## 1. 결론

파일은 디스크에 있다. 모델이 픽셀을 못 본 것이다.

문장에 「코드」가 있으면 채팅은 Tesseract를 건너뛰고, Hermes가 켜져 있으면 비전 추출도 건너뛴다. 모델에게는 `@"파일명"`만 간다. 문장에 「코드」가 없으면 Tesseract가 도는데, 언어팩 경로에 따옴표가 붙어 `TesseractError`로 죽는다.

시험 사진은 프로그램 2-3 OpenCV 예제다. `import cv2 as cv`, `soccer.jpg`, 가로·세로 0.5 축소. 같은 그림이 붙여넣기 두 장과 스크린샷 한 장이다.

## 3. 구조

```text
채팅 전송
└─ MainWindow 첨부 분기 (main_window.py, 첨부 처리)
   ├─ 이미지만 있고 문장에 작성|넣어|써|스크립트|코드
   │  └─ AttachmentWorker 를 타지 않음
   │     └─ _continue_user_turn
   │        ├─ Hermes 켜짐 → 사진 코드 파이프 생략
   │        │  (allow_image_pipe and not owns)
   │        ├─ 자료 읽기: 이미지 파일은 skip
   │        └─ Hermes 텍스트 채팅
   │           본문 = 질문 + [첨부 파일] @"파일명"
   │           픽셀 없음, 절대 경로 없음
   └─ 그 외 이미지 (스크린샷만, 빈 문장)
      └─ AttachmentWorker
         └─ attachment_context._ocr_image
            └─ pytesseract --tessdata-dir "경로"
               └─ TesseractError
                  ├─ 다른 첨부에 본문이 있으면 Hermes가 오류 메타로 답함
                  └─ 이미지뿐이면 턴 중단, 오류 한 줄만 표시
```

이번 요청이 갈라지는 곳: 「코드」가 있으면 위 갈래, 없으면 아래 갈래. 두 갈래 모두 비전(`extract_image_code`, `page_vision.transcribe_images`)에 도달하지 않았다.

예전 동작: Hermes가 꺼져 있으면 `_handle_image_code_pipe`가 이미지 바이트를 비전 모델에 보내고, 코드를 열린 파일에 썼다. Hermes를 켜면 그 가로채기를 끄고 `project.write_image_code` 도구에 맡기도록 바꿔 두었다 (`hermes_owns_local_intents`). 도구는 절대 경로가 있어야 파일을 연다. 채팅 문장은 파일명만 준다.

## 5. 개선안

빈 자리는 세 곳이다.

1. 「코드」+이미지일 때 OCR을 빼는 분기와, Hermes라서 비전 파이프를 빼는 분기가 겹치면 픽셀을 읽는 함수가 없다.
2. 모델 도구에 주는 값이 화면용 파일명이다. 도구가 요구하는 값은 디스크 경로다.
3. 채팅 이미지 OCR의 tessdata 인자가 PDF OCR과 다르다. 따옴표 때문에 언어팩을 못 연다. 예외 원문도 채팅에 남지 않는다.

따옴표만 고쳐도 이 교재 캡처는 `import ov2 as cv`로 나온다. 코드 추출은 Tesseract 복구와 별도로 비전 경로가 있어야 한다.

## 7. 조치

1. 코드 문장 + 이미지: Hermes가 켜져 있어도 절대 경로로 비전 추출이 실행되거나, 도구 인자에 그 경로가 들어가야 한다.
2. 그 외 이미지: `_ocr_image`의 tessdata 인자를 `_ocr_png_bytes`와 같게 두고, 실패 시 `TesseractError` 본문을 남긴다.
3. 코드가 목표면 Tesseract 결과를 그대로 파일에 쓰지 않는다. 위 1의 비전 결과를 쓴다.

아래 8–10이 이 조치의 구현 기준이다. 문장에 「코드」가 있는지로 읽는 방법을 나누지 않는다.

## 9. 키워드 분기는 휴리스틱이다

결론: 이미지를 읽는 판단이 글자 포함 정규식이다. 픽셀을 보지 않는다.

조건은 `file_write_claim.image_write_request`다.

```text
문장에 작성|넣어|써|스크립트|코드 가 있고
첨부 확장자가 png|jpg|jpeg|webp|gif|bmp 이면 True
```

단어 경계가 없다. 「코드」는 「코드를」「바코드」에도 맞는다. 「써」는 「써줘」뿐 아니라 그 음절이 들어간 문장에도 맞는다. 「이 사진 읽어줘」「글자만 뽑아줘」, 빈 문장 스크린샷은 맞지 않아 OCR로 간다.

그래서 1절의 「코드」 있음/없음은 인식 품질 차이가 아니다. 읽기 전에 갈래를 고르는 휴리스틱이고, 지금 두 갈래 모두 픽셀을 모델에게 넘기지 못한다.

인식 자체는 휴리스틱이 아니다. 비전은 이미지 바이트를 보고, Tesseract는 픽셀을 본다. 다만 그 함수까지 가게 하는 문이 문장 정규식이다.

| 계층 | 하는 일 | 휴리스틱인가 |
|---|---|---|
| `image_write_request` | 읽기 경로를 문장으로 고름 | 예 |
| `images_only` 조기 return | 그 문장이면 OCR을 건너뜀 | 예. 비전으로 이어지지 않음 |
| `skip_image_files` | 같은 문장이면 자료 비전을 건너뜀 | 예 |
| `transcribe_images` / `extract_image_code` | 바이트를 모델에 보냄 | 아니오. 이번 턴은 호출 안 됨 |
| `_ocr_image` | 픽셀을 Tesseract에 보냄 | 아니오. 경로 따옴표로 실패 |

## 10. 구현

결론: 어떤 문장이든 이미지를 먼저 읽고, 그 다음 사용자 문장으로 할 일을 정한다. 문장으로 읽기 여부를 정하지 않는다.

```text
첨부 확장자가 이미지
└─ PIL로 PNG 바이트 (이미 있는 _png_bytes. png jpg jpeg webp gif bmp, 채팅은 tif/tiff 포함)
   └─ 비전 1회 (page_vision.transcribe_images)
      프롬프트 = 사용자 문장 그대로
      「보이는 것만. 없으면 빈 문자열」
      └─ 본문 + 절대 경로를 채팅 컨텍스트에 넣음
         └─ Hermes가 그 본문으로 답하거나 도구를 호출
            파일에 쓸 때만 project.write_file 또는 project.write_image_code
            image 인자는 절대 경로
   └─ 비전 결과가 비면
      content_extract._ocr_png_bytes 와 같은 tessdata 인자로 OCR
      코드 파일에는 쓰지 않음. 실패 사유는 예외 타입 이름이 아니라 본문
```

| 단계 | 맡는 일 | 판단 |
|---|---|---|
| 정규화 | 형식마다 다른 디코더를 두지 않고 PNG 한 가지로 통일 | 기존 `_png_bytes` |
| 읽기 | 문장과 무관하게 비전. 키워드 조기 return 삭제 | `images_only and image_write_request` 분기를 없앤다 |
| 전달 | 화면용 `@"파일명"`과 별도로 모델 컨텍스트에 절대 경로와 전사 본문 | 10-02 이전 경로 형식 복구. 파일명 칩은 화면에만 |
| 수행 | 추출만이면 전사 본문을 답으로. 파일 변경이면 도구가 디스크에 쓴 뒤 ok | 완료 문장 게이트는 유지 |
| OCR | 비전 실패 시에만. PDF와 같은 `--tessdata-dir` | 따옴표 있는 `_ocr_image` 설정은 쓰지 않음 |
| Hermes가 꺼진 때 | 기존 로컬 파이프는 그대로 둬도 된다 | 읽기 생략 조건으로는 쓰지 않음 |

완료 기준:

1. 「이 사진속 코드를 텍스트로 추출해줘」와 빈 문장 스크린샷이 같은 읽기 함수를 탄다. `stage=extract` 또는 비전 전사 로그에 글자가 있다.
2. 모델 요청에 절대 경로가 있고, `@"파일명"`만으로 `image file required`가 나지 않는다.
3. 이번 OpenCV 캡처의 전사에 `import cv2`와 `soccer.jpg`가 있다. Tesseract의 `import ov2`를 파일에 쓰지 않는다.
4. 「테스트 파일에 넣어줘」는 전사 뒤에 쓰기 도구만 호출한다. 읽기 자체를 그 문장이 켜지 않는다.
