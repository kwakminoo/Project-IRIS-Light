확인은 2026-10-12 공개 페이지와 2026-10-13 소스 대조다. 인스타그램은 임베드 캡션, 유튜브는 영상 설명, 저장소는 README다. 세 번째 카드 이미지는 공개 임베드에 제품명이 없어 제품명까지 확정하지 않았다.

## 1. 결론

대회 빌드에 이 저장소들을 집어넣지 않는다. 가져올 것은 코드 덩어리가 아니라, 헤르메스를 아이리스 안으로 옮긴 뒤에 쓸 네 가지다. 작업 칸, 기억, 스킬 등록, 안전 문.

왼쪽 아이콘 중 기능이 없는 자리는 인스타그램, 디스코드, 카카오톡, 텔레그램이다. IDE, 메일, 캘린더, 안드로이드, 위키는 연결되어 있다. 빈 칸은 메신저 흉내가 아니라 바깥 앱을 여는 목록이 된다.

## 3. 구조

아이콘을 누르는 길과, 나중에 확장이 갈라지는 곳이다.

```text
왼쪽 아이콘
  └─ utility.actions.add_icon_action
       ├─ callback 있음
       │    IDE / 메일 / 캘린더 / 모바일 / 위키
       └─ callback 없음  ← 이번 빈 칸
            instagram, discord, kakao, telegram
              └─ set_default_callback
                   └─ _show_assistant_workspace
채팅 명령 workspace.open_instagram 등
  └─ ws_stub
       └─ err_result "준비 중"

이후 갈림
  ├─ 지금: 스텁 제거만. 저장소는 넣지 않음
  ├─ 확장: 빈 칸 = 바깥 앱 실행 목록
  ├─ 흡수: 헤르메스 루프를 아이리스 도구로
  └─ 연구: 필요한 회로만 깨우는 구조
```

이번 조사는 스텁 분기 다음이다. 채팅 모델, 위키 저장, IDE 타일은 이 분기 밖에 있다.

## 6. 개선안

빈 자리는 네 곳이다.

1. 아이콘 스텁 대신 실행 목록. 칸마다 이름과 바깥 명령만 둔다.
2. 위키의 「이 자료로 공부」. teach의 자료 칸은 위키를 가리키고, 수업 파일은 위키 밖에 둔다.
3. 스킬 등록 문. 테스트가 통과할 때만 남기고, 실패하면 되돌린다. 아이리스 핵심 파일은 에이전트가 고치지 못한다.
4. 영상 칸. 장면 목록과 사람 확인은 OpenMontage 모양. 렌더는 설치된 LTX가 있을 때만.

## 7. 차용

| 이름 | 가져올 부분 | 이번에 가져오지 않는 이유 |
|---|---|---|
| OpenMuse | 작업이 화면에 남고, 브라우저를 사람이 이어받음 | Intelligence 키와 Node 앱 전체는 아이리스 밖에 있음 |
| LibreOffice, GIMP, Krita | 실행만 | 편집기 재구현은 범위 밖 |
| Brahma Evo | 스킬은 등록되는 코드 | Evo 라이선스 미확인. 자기수정은 안전 문 다음 |
| Compound Engineering | 끝난 일의 배운 점을 위키에 남기는 순서 | 클로드 코드 플러그인을 앱에 넣지 않음 |
| teach | `MISSION`, `RESOURCES`, 수업, 학습 기록 | 위키를 학습장이 덮으면 원본이 사라짐 |
| k-skill | 맞춤법, 윤문, 글자 수 | 125개 일괄 설치는 인증·프록시·결제 칸을 염 |
| OpenMontage | YAML 단계와 사람 확인 | 제작 도구 묶음은 영상 칸 이전에는 쓸 곳이 없음 |
| LTX-2.5 | GPU가 있을 때의 렌더 호출 | 커뮤니티 라이선스. 22B를 설치본에 넣지 않음 |
| Archify | 없음 | 이미 들어 있음 |
| Graft, Codebase Memory MCP, GSD, webapp-testing, Agency Agents | 없음 | 개발 도구이거나 지금 구조와 겹침. 230명 역할은 항상 켜 두면 안 됨 |

초파리 연결체(FlyWire)는 코드를 베끼는 대상이 아니다. 나중에 볼 질문은, 버섯체처럼 대부분 잠들어 있다가 그 일만 켜지고 배운 것은 다른 기억에 쓰는지다. Agency Agents를 전부 켜 두는 모양은 그 질문과 반대다. k-skill의 분야와 OpenMontage의 단계가 그 실험에 가깝다.

## 8. 단계

### 1단계. 대회

헤르메스는 아이리스 뒤의 엔진으로 둔다. 결과: 저장소 흡수 없음. 완료 기준: 설치본 동작이 이번 조사와 무관하게 유지된다.

### 2단계. 칸

더미 아이콘 넷을 빼거나, 바깥 앱 실행 목록으로 바꾼다. 결과: 문서·이미지·영상은 바깥 앱, 아이리스는 그 옆에 선다. 완료 기준: `준비 중` 스텁이 화면에 없고, 실행 목록에 없는 칸은 비서 화면으로 떨어지지 않는다.

### 3단계. 흡수

헤르메스의 도구 루프를 아이리스 도구로 옮긴다. 결과: 작업 칸, 위키 기록, 한국 조회, 스킬 등록이 도구가 된다. 완료 기준: 스킬 추가가 테스트를 통과할 때만 남고, 핵심 파일은 잠겨 있다.

### 4단계. 연구

초파리 연결체로 회로를 깨우는 방식을 본다. 결과: 보고서와 실험. 앱을 그 구조로 갈아 끼우지 않는다. 완료 기준: 항상 켜 두는 역할 묶음과, 필요할 때만 켜는 묶음을 같은 과제로 비교한다.

### 5단계. 범용 에이전트

언어 모델은 바꾸는 부품으로 둔다. 결과: 아이리스가 도구, 기억, 화면을 직접 가진다. 완료 기준: 모델을 바꿔도 작업 칸과 위키와 앱 실행이 남는다.

## 9. 조치

1. 이 문서는 조사다. 코드 변경은 하지 않는다.
2. 더미 아이콘 제거와 실행 목록은 별도 구현으로 연다.
3. k-skill, LTX, OpenMuse, Brahma, Agency Agents는 기본 설치에 넣지 않는다.
4. 흡수 순서는 2단계 칸, 3단계 헤르메스, 그 다음 위키 학습과 영상 파이프라인이다.
