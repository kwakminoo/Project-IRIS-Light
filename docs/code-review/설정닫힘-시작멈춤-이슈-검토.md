## 2. 이슈 A — 설정창 닫으면 앱 종료

### 2.1 증상·환경 차이

| 항목 | 내용 |
|------|------|
| 보고 | 다른 PC에서 Setup 설치 후, 설정창을 열고 닫으면 IRIS 전체가 사라짐 |
| 개발 PC | 동일 동작 정상 |
| 해석 | 기능 로직 분기보다 **OS/GPU/DPI·Qt 네이티브 경로 크래시** 또는 **lastWindowClosed 종료** 쪽이 유력 |

### 2.2 코드 경로

| 단계 | 위치 | 동작 |
|------|------|------|
| 열기 | `main_window.py` `_open_settings_dialog` | `SettingsDialog(..., parent=self)` → `dlg.exec()` |
| 생성 | `settings_dialog.py` / `hud_dialog.py` | `QDialog(parent)` + Maximize/Minimize 힌트 |
| 닫기 | `closeEvent` / `reject` / `accept` | 음성 워커 `wait(1500)` 후 `super().closeEvent` |
| 앱 진입 | `__main__.py` | `QApplication` 생성 후 **`setQuitOnLastWindowClosed` 미설정** (기본 True) |

### 2.3 원인 후보 표

| 연번 | 가설 | 근거 | 타 PC에서만? | 신뢰도 |
|------|------|------|--------------|--------|
| A1 | **Frameless 메인 + modal 자식 다이얼로그 크래시** | `main_window.py` SetupWizard 주석: *「frameless MainWindow + modal child가 Windows에서 0xC0000409 크래시」* → 위저드는 `parent=None`. **Settings는 여전히 parent=MainWindow** | GPU/드라이버·DPI 차이로 간헐 | **높음** |
| A2 | `QuitOnLastWindowClosed` | 다이얼로그만 “마지막 창”으로 잡히면 `exec` 종료와 함께 프로세스 종료. Frameless/숨김 인트로 중 메인 인식이 흔들릴 여지 | OS/Qt 빌드 차이 | 중간 |
| A3 | 닫을 때 멀티미디어 해제 크래시 | Settings가 `QSoundEffect`·`PcmPlayer` 보유, `closeEvent`에서 stop | 오디오 장치 없는 PC | 중간 |
| A4 | 「제한 없음」→ `app.quit()`/`sys.exit(0)` | `settings_dialog.py` elevation 경로 | 권한 콤보를 건드렸을 때만 | 낮음 (단순 열고 닫기와 불일치) |
| A5 | `closeEvent`가 닫기를 거부 | `_stop_voice_playback(wait=True)` 실패 시 `event.ignore()` → **창이 안 닫힘**이지 앱 종료 아님 | — | 증상 불일치 |

### 2.4 권장 수정 (미적용 — 검토만)

| 우선 | 조치 | 비고 |
|------|------|------|
| 1 | `_open_settings_dialog`에서 `parent=None` (또는 약한 parent) + 위치만 메인 근처로 | SetupWizard와 동일 계약 |
| 2 | `__main__.py`에서 `app.setQuitOnLastWindowClosed(False)` + 메인 `closeEvent`에서만 `app.quit()` | 고아 다이얼로그로 앱이 죽지 않게 |
| 3 | Settings 닫기 시 음성 stop을 `wait=False` 또는 상한 짧게 + 예외 삼킴 | A3 완화 |
| 4 | 재현 PC에서 `%LOCALAPPDATA%\iris-light\launcher.log` / WER `0xC0000409` 확인 | 가설 A1 확정용 |

## 3. 이슈 B — 기동 시 환경확인 / 애니메이션 / 클라우드 확인 멈춤

### 3.1 정상 부팅 파이프라인

| 순서 | 함수 | UI에 보이는 것 | 블로킹 여부 |
|------|------|----------------|-------------|
| 1 | `_begin_startup_gate` | 「환경 확인 중…」 | `StartupHealthWorker` (프로브 최대 **90s**) |
| 2 | `_start_runtime_boot` → `_begin_boot_sequence` | 인트로 `prepare_hidden` + 애니메이션 | UI 스레드 애니 |
| 3 | `_refresh_models` | 「클라우드 모델 확인 중…」 | `OllamaModelListWorker` + **`list_chat_models(probe_cloud=True)`** |
| 4 | `notify_models_ready` | 인트로 완료 조건 | 모델 콜백 필수 |
| 5 | `_on_intro_finished` | 준비완료 메시지·Hermes health·업데이트 체크 | 인트로 `finished`에 종속 |

### 3.2 멈춤 후보 표

| 연번 | 구간 | 코드 | 멈춤 체감 | 신뢰도 |
|------|------|------|-----------|--------|
| B1 | 클라우드 모델 확인 | `ollama_workers.py` → `list_chat_models(probe_cloud=True)` → 카탈로그+모델별 `probe_model_status` (스레드풀, **전역 타임아웃 없음**) | 상태줄에 「클라우드 모델 확인 중…」 장시간. 인트로 모션은 끝나도 `_models_ready` 대기로 **글리치 홀드 루프** (`startup_intro._try_complete`) | **높음** |
| B2 | 환경 확인 | `StartupHealthWorker` 90s join. `core_ready`면 즉시 True이나, 아니면 `_warm_core_services`(Ollama/Hermes 기동 대기) | 「환경 확인 중…」만 길게 | 높음 (느린 PC·재부팅 직후) |
| B3 | 인트로↔모델 결합 | `startup_intro.py`: motion 완료 후에도 `not _models_ready`면 180ms 홀드 반복, `finished` 미방출 | 애니 후 UI·Hermes·준비완료 메시지 안 뜸 | **높음** (B1의 결과) |
| B4 | `_start_runtime_boot` 조기 return | `ui_mode != normal` 또는 hero pending이면 `_runtime_boot_started=True`만 찍고 **인트로/`_begin_boot_sequence` 미실행** | 「시작 안 됨」 | 중간 (콜드스타트는 `normal`이라 드묾, IDE 왕복 레이스) |
| B5 | `prepare_hidden` 폭 0 | 주석: 게이트가 빠르면 폭 0 arm → 인트로 안 보임 | “멈춘 것처럼” 빈 창 | 중간 (이미 40ms 지연으로 완화 시도) |
| B6 | SetupWizard Core 단계 | 클라우드 로그인/최소 모델 카드에서 사용자 입력 대기 | 위저드에서 정지 (앱 hung과 구분) | 설치 직후 혼동 가능 |

### 3.3 권장 수정 (미적용 — 검토만)

| 우선 | 조치 | 기대 효과 |
|------|------|-----------|
| 1 | `OllamaModelListWorker`에 전체 작업 하드 타임아웃(예: 15–20s). 초과 시 local only emit 또는 `failed` | 「클라우드 모델 확인 중」무한 대기 제거 |
| 2 | 인트로: 모델 대기 상한(예: 8s) 후 `notify_models_ready` 강제 → `_on_intro_finished` 진행 | 애니·준비완료가 네트워크와 분리 |
| 3 | 기동 시 `probe_cloud=False`로 1차 목록, 이후 백그라운드 프로브 | 체감 기동 속도 |
| 4 | 「환경 확인 중」에 경과 초/단계 로그 (`live_activity`) | 90s 대기를 “멈춤”과 구분 |
| 5 | B4: early-return 시 `_runtime_boot_started`를 올리지 않거나, hero 종료 후 boot 재예약 | IDE 레이스 방지 |
