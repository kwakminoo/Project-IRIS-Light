## 1. 결론

세션 분리는 들어갔다. 대화 id마다 `ChatRunSlot`이 있고, 전환은 진행 중 워커를 취소하지 않으며, 동시 루프는 2다. 프로젝트 쓰기와 위키 노트 경로에는 잠금이 있다.

아직 한 창에 남은 것이 둘이다. 턴의 비동기 이어짐이 대화 슬롯 바인딩을 놓고, 모델 호출은 게이트웨이 기본 모델을 통째로 바꾼다. 그래서 채팅을 옮긴 뒤의 첨부·자료 읽기·이전 대화 검색은 보고 있는 채팅의 기록과 프롬프트로 샐 수 있다. 모델이 다른 두 채팅은 서로의 기본 모델을 덮는다.

2단계는 그 바인딩을 턴이 끝날 때까지 유지하고, 요청마다 `model`과 `provider`를 싣는 일이다. 3단계는 Git worktree다. 헤르메스 프로세스와 `iris/core`는 그대로 둔다.

## 2. 구조

```text
키보드 _on_user_text(session_id = 화면의 대화 id)
  └─ UserTurnDispatcher.submit
       ├─ 그 id가 비었고 실행 중 < 2 → turn_ready
       └─ 아니면 그 id의 대기열 (concurrent_cap | busy)
            └─ _execute_user_turn
                 ├─ _bound_slot = 그 id의 ChatRunSlot     ← 이 함수의 finally에서 해제
                 ├─ 동기 구간: 기록·게이트·모델 피커를 그 슬롯으로
                 └─ 비동기 이어짐 (첨부, 자료 읽기, 이전 대화 검색)
                      └─ 콜백 시점에는 _bound_slot 이 없음
                           └─ 화면 대화의 기록·전역 프롬프트 필드를 읽음
                                └─ HermesChatWorker
                                     ├─ set_inference_model (게이트웨이 기본 모델)
                                     └─ POST /v1/chat/completions
                                          model, messages, stream
                                          provider 없음, 세션 헤더 없음
토큰 콜백 _on_*_for_turn
  ├─ 그 턴의 대화 == 화면 → 화면·TTS
  └─ 아니면 pending_partial / DB / away_reply
전환 _load_conversation
  └─ 기록·구체만 교체. request_cancel 없음
       └─ 떠나기 전 화면 버퍼 → 떠나는 슬롯의 pending_partial
       └─ TTS 정지. 돌아온 슬롯의 away_reply 를 한 번 읽음
쓰기 call_registered
  └─ SessionWriteLock (프로젝트 하나, 위키 상대 경로마다 하나)
```

갈라지는 지점은 두 곳이다. `_execute_user_turn`의 `finally`가 슬롯 바인딩을 푸는 곳, 그리고 `HermesChatWorker.run`이 `set_inference_model`로 기본 모델을 쓰는 곳.

위키 `projects/<슬러그>/chats/<대화 id>.md`는 끝난 글의 보관이다. 슬롯의 키가 아니다. 키는 대화 id다.

## 3. 코드 리뷰

| 지점 | 2026-10-11에 하는 일 | 동시 작업을 아직 막는 이유 |
|---|---|---|
| `ChatRunMap` | `MainWindow.__init__`에서 만든다. 대화 id → 워커, 점유, 이어하기, `pending_partial`, `away_reply` | 슬롯을 지우지 않는다. 삭제한 대화의 워커를 취소하지 않는다 |
| `SlotAttr` | `_chat_worker`, 이어하기, `tool_ok_count`, 위키 이동 플래그를 `_slot_now()`로 보낸다 | `_bound_slot`이 없으면 화면 슬롯이다 |
| `UserTurnDispatcher` | 대화 id별 `_active`. `MAX_CONCURRENT = 2`. 셋째는 대기 | 음성 정지가 `clear_pending()`으로 모든 대화의 대기열을 비운다 |
| `_load_conversation` | 화면과 구체만 바꾼다. 검사는 워커 `cancelled`가 거짓인 것을 본다 | 비동기 이어짐은 이 함수가 보호하지 않는다 |
| 토큰 콜백 | 화면이 아니면 그 대화의 `pending_partial`과 DB에만 붙인다 | 사용자 말풍선(`_continue_user_turn`)은 화면 위젯에 무조건 붙인다 |
| `_with_past_chats` | 이전 대화·위키·코드 노트를 찾은 뒤 워커를 띄운다 | `_pending_past_chats` 등이 창에 하나다. 검색 대화 id는 `self._conversation_id`(화면)다 |
| `HermesChatWorker.run` | 채팅 스트림 전에 `set_inference_model` | 런 둘이면 기본 모델 쓰기가 겹친다 |
| `stream_chat` | `model`, `messages`, `stream` | `provider`가 없으면 공개 문서상 기본 모델로 떨어진다. `resolve_request_model`은 광고 모델이 하나면 그 이름으로 바꾼다 |
| `SessionWriteLock` | `project.*` 쓰기·`ide.edit/save/task/debug`는 창에 하나. 위키 쓰기는 경로마다 | `wiki.move_notes`, `note.export_pdf`, `ide.open_folder`, `project.create_scaffold`는 표 밖이다. 경로를 `normpath`하지 않는다 |
| 음성·구체 | 마이크·TTS·구체는 화면 채팅만 따른다. 전환 시 TTS를 멈추고, 자리 비운 동안 끝난 답은 돌아올 때 한 번 읽는다 | 음성 정지는 화면 슬롯만 취소하면서 대기열은 전부 버린다 |
| 메일·캘린더 | 워커가 따로 있다 | 같은 `set_inference_model`로 게이트웨이 기본 모델을 바꾼다. 채팅 슬롯 맵의 본보기가 아니다 |

하지 않은 일. 설치본 `/v1/capabilities` 실측, 헤르메스 소스 수정, Git worktree, 검사 재실행.

## 4. 개선안

빈 자리는 네 곳이다.

1. 턴이 비동기로 이어질 때도 `_bound_slot`을 그 대화에 다시 묶기. 프롬프트 조각(`_pending_past_chats`, 위키·코드·웹 증거, 질문 종류)을 슬롯에 두기.
2. 채팅 워커가 `set_inference_model`을 호출하지 않기. 그 요청에 `model`과 `provider`를 싣기. 슬롯이 고른 모델을 기억하기.
3. 쓰기 잠금의 경로를 정규화하고, 노트를 옮기거나 PDF·폴더를 여는 쓰기를 같은 표에 넣기.
4. 음성 정지의 대기열 삭제와, 채팅 삭제 시의 슬롯 취소를 그 대화 id로 한정하기.

Git worktree와 게이트웨이 프로세스 분리는 이 빈 자리가 아니다.

## 5. 차용

| 이름 | 가져올 부분 | 이번에 가져오지 않는 이유 |
|---|---|---|
| 대화 id + `ChatRunSlot` | 이미 슬롯의 키다 | 새 저장소를 만들지 않음 |
| 헤르메스 요청 단위 모델 | `model`과 `provider`를 그 POST에만 싣는다. 우선순위는 세션 덮어쓰기 → 라우트 별칭 → 요청 필드 → 전역 기본 | 게이트웨이 소스를 고치지 않음. `session_model_pool`에는 의존하지 않음 |
| `X-Hermes-Session-Id` | 같은 완료 API에 대화 id 헤더 | Sessions API로 호출을 갈아타지 않음 |
| 경로 잠금 | 지금 `SessionWriteLock` | 샌드박스 디스크를 새로 만들지 않음 |
| Git worktree | 3단계에서 폴더를 나눔 | 1·2단계의 조사와 모델 분리에는 폴더 사본이 필요 없음 |
| LangGraph·AutoGen·Claude Agent SDK | 없음 | 막는 층이 아이리스의 슬롯 바인딩과 전역 모델 쓰기라 런타임 교체로 사라지지 않음 |

## 7. 조치

1. 2단계는 IRIS-IMPL-2026-1011-01만 구현한다. 그 명세의 바인딩과 요청 단위 모델이 끝나기 전에 worktree를 넣지 않는다.
2. 잠금 누락, 채팅 삭제 시 워커 유지, 음성 정지의 전체 대기열 삭제는 1단계 잔여다. 2단계 모델 필드와 한 변경으로 섞지 않는다.
3. 착수 전 설치본 `/v1/capabilities`와 `max_concurrent_runs`를 본다. 문서 기본은 10이고, 넘으면 HTTP 429다.
