# Prompt: 채팅 이미지·스크린샷은 문장과 무관하게 읽는다

기준: `docs/code-review/이미지인식-채팅첨부-원인.md` 10절.

```text
Context:
- 문장에 작성|넣어|써|스크립트|코드 가 있으면 이미지 OCR을 건너뛰고, Hermes가 켜져 있으면 비전 파이프도 건너뛴다.
- 채팅 문장은 @"파일명"만 가진다. project.write_image_code 는 절대 경로가 필요하다.
- 키워드가 없으면 _ocr_image 가 --tessdata-dir "{경로}" 로 TesseractError 가 난다.
- 모델 정리는 state=unavailable 을 피커에서 뺀다. 사용자는 전체 목록과 쓸 수 있음/쓸 수 없음/적합하지 않음 구분을 원한다.

Goal:
1) 첨부 확장자가 이미지면 문장과 관계없이 읽는다. 키워드로 읽기를 건너뛰지 않는다.
2) PNG로 맞춘 뒤 비전 1회. 프롬프트는 사용자 문장. 보이는 것만. 빈 결과면 PDF와 같은 tessdata 인자로 OCR.
3) 화면 칩은 파일명. 모델 컨텍스트에는 절대 경로와 전사 본문.
4) 파일에 쓰는 일은 그 다음 도구. Tesseract 오인식(import ov2)을 코드 파일에 쓰지 않는다.
5) 모델 정리는 목록에서 빼지 않는다. 맨 위부터 쓸 수 있는 모델, 쓸 수 없는 모델, 적합하지 않은 모델.
   임베딩·도구 미지원은 적합하지 않음. probe 가 거절·구독 전용으로 남긴 것은 쓸 수 없음.
   설정에서 모델을 추가하고 모델 정리를 눌러도 같은 구분.

Constraints:
- 완료 문장 게이트, Hermes 로컬 가로채기 계약, 80:20 타일은 그대로.
- 새 OCR 엔진을 넣지 않는다. page_vision.transcribe_images 와 content_extract._ocr_png_bytes 를 쓴다.

Interface:
- attachment_context._ocr_image: 비전 reader 가 있으면 먼저. 없으면 _ocr_png_bytes. 실패는 ValueError 본문.
- images_only and image_write_request 조기 return 삭제. skip_image_files 를 그 정규식으로 켜지 않는다.
- apply_ollama_cleanup: unavailable 이어도 모델을 돌려준다. availability 를 채운다.
- usable_models: 프로브가 거절해도 이름 목록에서 빼지 않는다.
- 피커·브랜드 목록 정렬 키는 model_list_tier. 0 쓸 수 있음, 1 쓸 수 없음, 2 적합하지 않음.

검증:
.venv\Scripts\python.exe -m unittest tests.test_attachment_pipeline tests.test_ollama_model_cleanup
.venv\Scripts\python.exe -m iris.infrastructure.ollama_client
.venv\Scripts\python.exe -m iris.storage.api_providers
```
