# Prompt: 같은 저장소를 고치는 채팅은 폴더를 나눈다

기준: `docs/code-review/다중채팅-동시작업-3단계-착수검토.md`, `docs/code-review/다중채팅-동시작업-구현보고서.md` 3단계. 지금 소스(2026-10-13).

```text
Context:
- 2단계 바인딩과 요청 단위 모델은 들어가 있다. 이 경로를 다시 만들지 않는다.
  세션 헤더, 게이트웨이 주소·키 한 칸, 잠금 대기 시간, 표 밖 IDE 액션은 이 단계가 아니다.
- 프로젝트 루트는 profile.project_root 하나다. IDE 세션과 프로젝트 잠금도 창에 하나다.
  iris/ 에 git worktree 호출이 없다.
- 같은 저장소를 고치는 채팅은 그 폴더를 같이 쓴다. 위키 노트는 작업 폴더 사본이 아니다.

Goal:
1) 한 저장소를 먼저 쓰는 대화는 그 체크아웃을 유지한다.
   같은 저장소를 이후 대화가 쓰면 git worktree add 로 그 대화만의 폴더를 만든다.
   git 저장소가 아니면 경로를 그대로 둔다.
2) 그 대화의 프로젝트 루트, 파일 쓰기, 이름 변경, 실행, 폴더 열기는 그 폴더만 본다.
   작업 폴더 경로를 profile.project_root 에 덮어쓰지 않는다.
3) 본 트리로 합치는 명령은 없다. confirm 이 있어도 merge, cherry-pick, checkout 으로
   본 트리를 고치지 않는다. 위키 노트에 이 사본을 만들지 않는다.

Constraints:
- 헤르메스 소스, 게이트웨이, 세션 헤더, api_key 로그, direct_model_requests 는 넣지 않는다.
- SessionWriteLock 의 타임아웃과 잠금 표에 없는 IDE 액션은 넣지 않는다.
- 자동 병합, 자동 worktree 삭제, 위키 노트로 사본 만들기는 넣지 않는다.
- 슬롯 필드를 첫 콜백에서 새로 만들지 않는다. 작업 폴더 표는 모듈에 둔다.
- 프로세스가 다시 켜지면 표는 비고, 디스크의 worktree 는 그대로다.

Interface:
- work_root_for(conversation_id, requested) -> str
  저장소가 아니면 requested. 첫 대화는 그 체크아웃. 다음 대화는 worktree 경로.
- is_chat_worktree(path) -> bool. 이 단계가 만든 폴더만 참.
- describe_for_main(conversation_id, confirm=False) -> dict
  merged 는 항상 False. 사본이 있고 confirm 이 아니면 ok 는 False.
  confirm 이 True 여도 본 트리 파일은 바뀌지 않는다.
- project.worktree_status 는 describe_for_main 만 호출한다.
- 작업 폴더의 부모 디렉터리 이름은 <저장소이름>.iris-worktrees 다.
  브랜치 이름은 iris/chat-<대화 id> 다.

검증:
- tests/test_chat_worktree.py
  첫 대화는 본 체크아웃이다. 둘째 대화 경로는 다르고 git worktree 다.
  둘째 폴더에 쓴 파일은 본 트리에 없다.
  confirm true 뒤에도 그 파일은 본 트리에 없고, git 인자 목록에 merge 가 없다.
  git 이 아닌 경로는 그대로다.
- 기존 전환·이어하기 검사

.venv\Scripts\python.exe -m unittest tests.test_chat_worktree
.venv\Scripts\python.exe -m iris.ui._check_conversation_switch_cancel
.venv\Scripts\python.exe -m iris.ui._check_turn_followup
```
