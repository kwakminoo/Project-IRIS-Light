# Prompt: 위키 공부 — 인용 칩 · 선택 용어설명 · 페이지 메모장

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-PROMPT-WIKI-STUDY-001 |
| 작성일 | 2026-10-21 |
| 관련 | 위키 보면서 Iris와 공부 / 채팅 맥락 |
| 대상 | `ObsidianWorkspacePage`(`QTextBrowser` 본문), 워크스페이스 채팅 호스트, 로컬 메모 저장 |
| 목적 | 구현 전 합의된 UX를 한 번에 실행할 수 있는 프롬프트 |
| 상태 | 구현 완료 (2026-10-21) — `_check_wiki_study_ux` / `test_wiki_page_memos` 통과 |

## 0. 합의된 방향 (요약)

1. **채팅 인용 칩**: 열린 위키에서 복사·붙여넣기(또는 드래그)하면 평문이 아니라 **푸른 인용 카드**(상단=위키 제목, 본문=선택 텍스트, 하단=경로/쪽수 가능하면). 모델에는 메타(`note_rel`, `title`, `quote`) 포함.
2. **선택 용어설명 (형광펜 설명 대체)**: 본문에서 드래그 선택(푸른 하이라이트)이 생기면, 선택 영역 **맨 우측 상단**에 작은 **펼친 책** 아이콘. 클릭 시 그 단어·구의 **짧은 뜻/설명** 팝오버. “설명해줘”를 채팅에 보내는 플로우가 아님.
3. **페이지 메모장**: 퀴즈모드·위키 폴더에 새 노트 저장 **하지 않음**. 열린 위키 **내용 영역 우측 상단**에 **메모장** 아이콘 → 누르면 이 페이지에 묶인 메모 목록/작성 UI. 저장 위치는 vault 밖(Iris DB 또는 `~/.iris-light` 사이드카).
4. **하지 말 것**: 노란 형광펜 후 “설명해줘” 전용 버튼, 퀴즈 모드, 위키 폴더에 학습 노트 자동 생성.

## 1. 차용 / 참고 (오픈소스)

구현 시 **의존성으로 끌어오지 말고**, UX·데이터 모델만 참고한다. AGPL 등 라이선스에 묶이는 코드 복사는 하지 않는다.

| 이름 | 가져올 부분 | 이번에 가져오지 않는 이유 |
|---|---|---|
| [TipTap BubbleMenu](https://tiptap.dev/docs/editor/extensions/functionality/bubble-menu) | 텍스트 선택 시 선택 근처 floating action | Iris 본문은 `QTextBrowser`(Qt). TipTap/ProseMirror를 넣지 않음. **패턴만** (selection → 앵커 좌표 → 작은 버튼). |
| [Readest DictionaryPopup / Context Dictionary](https://github.com/readest/readest) | 선택 → 사전/문맥 설명 카드, 짧은 설명 | Electron/React 리더. UI 골격만. 사전 엔진·구독 플로우는 불필요. Iris는 로컬/게이트웨이 LLM으로 “한 단락 설명”. |
| [Floating Dictionary (KOReader)](https://github.com/DisastrousPatience83/Floating-Dictionary.koplugin) | 선택 옆 컴팩트 정의, 읽기 흐름 유지 | Lua/KOReader 전용. “짧게 보고 읽기 재개” UX만. |
| [text-polish Chrome extension](https://github.com/hellokaton/text-polish-chrome-extension) | selection floating menu (explain/translate) | 브라우저 확장. Qt에 맞게 재구현. |
| [Hypothesis](https://web.hypothes.is/) / [obsidian-annotator](https://github.com/elias-sundqvist/obsidian-annotator) | 문서 단위 annotation 메타(quote + comment) | AGPL·웹 주석 스택. **페이지 키 + quote + memo body** 스키마만. vault에 md 주석 파일 쓰지 않음. |
| [mdwys memos](https://github.com/takeshy/mdwys) | 문서별 타임라인 메모, 하이라이트↔메모 점프 | 메모를 별도 md로 vault 옆에 둠. 우리는 **vault에 새 파일 금지** → Iris 로컬 저장으로만. |

찾지 못한 것: PyQt6 `QTextBrowser` 전용 “selection corner FAB” 기성 위젯. **직접 얇게 구현**하는 편이 맞다 (`QTextCursor` + `cursorRect` + 오버레이 `QToolButton`).

## 2. 구조 (요청 경로)

```
[위키 본문 QTextBrowser]
  ├─ selectionChanged
  │    └─ SelectionBookFab (선택 rect 우측 상단)
  │         └─ click → TermExplainPopover
  │              └─ 짧은 설명 (LLM 또는 캐시)  ※ 채팅 턴을 열지 않음(기본)
  ├─ NoteHeader / 내용영역 우측 상단
  │    └─ NotepadIcon → PageMemoPanel (이 note_rel 전용)
  │         └─ CRUD → Iris local store (vault 밖)
  └─ copy / drag → ChatHost
       └─ WikiQuoteChip (푸른 카드) → UserTurn 메타 → Hermes/모델

[채팅 일반 붙여넣기]
  └─ 위키 출처 메타 없으면 평문 유지
```

갈라지는 지점: **용어설명 = 인플레이스 팝오버**, **공부 질문 = 채팅 인용 칩**. 두 경로를 섞지 않는다.

## 3. 구현 프롬프트 (에이전트용)

```text
Context:
- 위키 노트 본문은 iris/ui/workspaces/obsidian_workspace_page.py 의 QTextBrowser(_body).
- 원본 PDF는 QWebEngineView. 이번 범위의 선택 FAB·메모는 우선 마크다운 본문(_body)만.
- 워크스페이스 채팅은 workspace_iris_chat / chat_panel. 첨부·칩 패턴이 이미 있음.
- 목표: 위키를 보며 공부. Iris가 “지금 연 페이지 + 사용자가 집어 올린 구간”을 알게 함.
- 사용자 합의: 형광펜→설명해줘 없음. 선택 시 펼친책 아이콘→짧은 용어설명.
  퀴즈/위키폴더 새노트 없음. 내용영역 우측상단 메모장 아이콘→페이지 메모.

Goal:
1) WikiQuoteChip
   - 열린 위키에서 복사된 텍스트를 채팅에 붙이면 푸른 카드: 상단 노트 제목, 본문 quote, (가능하면) rel_path.
   - 드래그앤드롭도 같은 칩이면 좋음. 외부 평문 클립보드는 칩으로 승격하지 않음.
   - 전송 시 모델 컨텍스트에 note_rel, title, quote 를 구조화해 넣음. UI 미리보기와 본문 중복을 최소화.

2) Selection → 펼친책 FAB → TermExplain
   - _body 에서 선택이 유효(비어 있지 않음, 과도한 장문이면 상한)하면 선택 영역의 맨 우측 상단에 작은 펼친책 아이콘.
   - 이름은 UX상 Selection Toolbar / Bubble action. 코드 심볼 예: WikiSelectionBookFab.
   - 클릭 시 팝오버: 선택 문자열 + 2~5문장 쉬운 설명. 기본은 채팅 히스토리에 user/assistant 행을 남기지 않음.
   - 설명 생성은 짧은 로컬/게이트웨이 호출. 실패 시 한 줄 오류. 장문 에세이 금지.
   - 선택 해제·스크롤·노트 전환 시 FAB/팝오버 닫기.

3) Page Notepad
   - 열린 노트 내용 영역 우측 상단에 메모장 아이콘.
   - 클릭 시 패널: 이 note_rel 에 묶인 메모 목록 + 추가/수정/삭제.
   - 저장은 vault / 위키 폴더에 md를 만들지 않음. ~/.iris-light 쪽 SQLite 또는 json 사이드카.
   - 스키마 최소: note_rel, memo_id, body, created_at, updated_at. (선택 quote는 있어도 되고 1단계에서 생략 가능)
   - 노트 바꾸면 패널 내용도 그 note_rel 로 갱신.

Constraints:
- 위키 폴더에 학습용 새 노트/퀴즈 파일 생성 금지.
- TipTap, Hypothesis, Readest, mdwys 코드를 벤더링하지 않음. 패턴만.
- Qt 슬롯 예외로 앱이 죽지 않게. FAB/팝오버 parent는 본문 조상 위젯. orphan top-level 창 금지.
- frameless MainWindow 위에 네이티브 모달 남발 금지. 용어설명은 가벼운 팝오버/패널.
- CREATE_NO_WINDOW 등 콘솔 계약, IDE 80:20 타일 계약은 그대로.
- 원본 PDF WebEngine 선택 FAB는 이번 단계에서 필수 아님(후속).
- 범위 밖 UI 리팩터·테마 대공사 금지.

Interface (제안, 이름 조정 가능):
- WikiQuote: { note_rel, title, quote, source? }
- explain_term(selection: str, note_rel: str, surrounding?: str) -> str  # 짧게
- PageMemoStore: list/add/update/delete(note_rel, ...)
- ObsidianWorkspacePage: selection FAB + notepad button + emit quote for chat host
- Chat host: ingest WikiQuote → chip in composer

단계 권장:
- 1단계: PageMemoStore + 메모장 아이콘/패널 (LLM 없음, 검증 쉬움)
- 2단계: SelectionBookFab + TermExplain 팝오버
- 3단계: WikiQuoteChip (복사/붙여넣기·드래그) + 모델 메타
- (후속) PDF 선택, 칩 클릭 시 본문 점프, 메모에 quote 앵커

검증:
- 선택 없음 → FAB 없음. 선택 있음 → FAB가 선택 rect 우측 상단 근처.
- FAB 클릭 → 짧은 설명. 채팅에 자동 user 메시지 안 쌓임(기본).
- 메모 추가 후 앱 재시작해도 같은 note_rel 에 보임. vault 폴더에 새 md 없음.
- 위키에서 복사 → 채팅 붙여넣기 → 푸른 칩(제목+quote). 메모장 앱에서 복사한 텍스트는 평문.
- 자검 모듈 추가 권장: iris/ui/_check_wiki_study_ux.py (좌표/스토어/칩 직렬화 assert)
- .venv\Scripts\python.exe -m iris.ui._check_wiki
- 관련 unittest가 있으면 함께.

Output:
- 위 단계 순서대로 최소 diff. 프롬프트에 없는 퀴즈/형광펜설명/위키새노트 넣지 말 것.
- 끝나면 docs/prompts/ 이 파일은 구현 확인 후 completed/ 로 이동.
```

## 4. UX 디테일 (구현 시 고정)

### 4.1 펼친책 아이콘 (용어설명)

- 보이는 조건: `selectedText().strip()` 길이 1~N (예: N=80자). 문단 전체 드래그는 FAB 숨기거나 “채팅에 인용”만 유도.
- 위치: 선택 마지막 줄의 `cursorRect` 기준 **오른쪽 바깥 또는 우측 상단**. 화면 밖이면 안으로 clamp.
- 클릭 결과: 작은 카드. 제목=선택어, 본문=쉬운 설명. “채팅으로 이어서 묻기”는 **후속 옵션**(1단계 필수 아님).

### 4.2 메모장

- 아이콘만 상시 노출(배지로 개수 표시하면 좋음).
- 패널은 본문 위를 가리는 슬라이드/팝오버. 위키 그래프·원본 PDF 레이아웃을 깨지 말 것.
- 메모는 “이 페이지를 읽으며 적은 개인 필기”. 모델 기본 컨텍스트에 자동 주입하지 않음(사용자가 칩으로 올리지 않는 한).

### 4.3 인용 칩 vs 용어설명

| | 인용 칩 | 펼친책 |
|---|---|---|
| 목적 | Iris에게 근거 구간을 주고 질문 | 모르는 단어 즉시 해소 |
| 결과물 | 채팅 user 턴의 일부 | 일시 팝오버 |
| 저장 | 대화 기록 | 없음(설명 캐시는 선택) |

1. 이 프롬프트로 구현 착수 여부·1단계부터 할지 사용자 확인.
