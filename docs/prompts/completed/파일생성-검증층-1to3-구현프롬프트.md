# Prompt: 파일 생성 검증층(V) 1~3 구현

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-PROMPT-2026-1028-WRITE-V |
| 작성일 | 2026-10-28 |
| 기준 | `docs/code-review/파일생성-말로만완료-원인.md`, 테트리스 말로만작성 재현 |
| 선행 | `docs/prompts/파일생성-말로만완료-1to5-구현프롬프트.md` (1~5는 골격 반영됨) |
| 범위 | **검증층 V의 구멍만** — 허위완료 정규식, 로컬쓰기 파일명 출처, 빈응답/도구0 failover |
| 금지 | Hermes 교체, 새 PEV 프레임워크, goal/followthrough를 LLM 분류기로 전면 교체, 펜스 전면 폴백, 탐색기 refresh |

```text
/poteto-mode Feature

Context:
- Agent(Hermes) ON이면 채팅은 이미 ReAct 도구 루프(E)를 탄다.
  문제는 모델이 tool_calls 없이 「작성 완료」만 말하거나 빈 응답을 내는 것이다.
- 1~5 구현으로 settle_completion_claim / 파일 followthrough / 로컬 쓰기 골격은 있다.
  재현(테트리스)에서 남은 구멍:
  (A) 「코드는 작성을 완료했습니다」「코드를 짰」이 _CLAIM_RE에 안 걸림 → CHAT_ONLY 미첨부
  (B) plan_local_file_writes 가 파일명을 goal 에서만 봄 → assistant 의 tetris_king.py 무시, ask 만
  (C) followthrough 가 「write_file 호출하라」를 다시 보내도 gemma 빈 응답 → No reply, 파일 없음
- MCP 도구는 iris_invoke. project.write_file 은 action 이름이다.
- 전면 펜스→파일 폴백·이미지 파이프 부활 금지. iris_generated.py 발명 금지.
- goal / followthrough 의 규칙 기반은 이번 PR 에서 제거하지 않는다.
  (자율 LLM 분류기로 갈아끼우면 잘못된 쓰기가 더 위험. V는 코드 증거 유지.)

Goal (1~3만):

1) 허위 완료 정규식 보강 (표시 V)
   - file_write_claim._CLAIM_RE 에 테트리스류 완곡 표현을 넣는다.
     최소: 작성을 완료, 코드를 짰, 코드는 작성, 작성을 마쳤 (기존 패턴과 OR).
   - turn_followthrough._DONE 과 어긋나면 맞춘다.
     (「작성하겠」만 잡고 「작성을 완료」는 표시 게이트가 놓치는 상태 금지)
   - settle 정책 유지: 증거 없으면 원문 + CHAT_ONLY 한 줄. 원문 삭제 금지.
   - 위키·메일·일반 답 게이트 금지.
   - 자검: 「코드는 작성을 완료했습니다. 파일 이름은 tetris_king.py 입니다.」
     + verified_path 없음 → display 에 CHAT_ONLY.

2) 로컬 쓰기: assistant 단일 파일명 허용 (실행 V)
   - plan_local_file_writes(goal, assistant):
     a) file_create_goal(goal) 아니면 skip (유지)
     b) fences = assistant 펜스. 없으면 skip (유지)
     c) names = named_rel_paths(goal)
        비었고 fences 가 정확히 1개이면 named_rel_paths(assistant) 사용.
        assistant 에서 뽑은 이름이 정확히 1개일 때만 write.
        0개면 기존 ask. 2개 이상이면 ask (임의 선택 금지).
     d) goal names 와 fences 개수 불일치면 기존 ask (유지)
     e) iris_generated.py 금지 (유지)
   - MainWindow._maybe_local_file_create_write 경로는 그대로 plan 을 쓴다.
     surface.registry.invoke project.write_file, open=true, 성공 시 증거 갱신.
   - 자검: goal="테트리스킹 코드 작성한 다음에 실행해줘",
     assistant 에 tetris_king.py 언급 + python 펜스 1개 → kind=write, pairs[0][0]=tetris_king.py
     goal 에 이름 없고 assistant 에도 이름 없음 + 펜스 있음 → kind=ask

3) 파일 목표 + 도구 0 / 빈 응답 시 failover (회복 V)
   - 파일 생성 goal 이고 이번 턴 tool_ok_count==0 이며
     (a) 본문이 비었거나 Iris 「(빈 응답)」/ Hermes No reply 류 이거나
     (b) settle 이 CHAT_ONLY 를 붙인 허위 완료
     이면, 이미 켜진 model failover 설정을 존중해 다음 모델로 한 턴 더 시도한다.
   - failover 설정이 꺼져 있거나 체인이 비면: 채팅/활동에
     「도구로 파일을 만들지 못했다. 모델을 바꾸거나 파일 이름을 지정해 다시 요청하라」
     한 줄을 남기고 끝. 조용히 성공처럼 두지 말 것.
   - followthrough 의 「호출하라」 프롬프트만 반복하는 것으로 (a)를 때우지 말 것.
     빈 응답 턴은 continue 프롬프트보다 failover/명시 실패를 우선.
   - Hermes/게이트웨이 소스 대규모 수정 금지. Iris 쪽 _on_chat_finished /
     failover_prefs / 기존 HermesChatWorker attempts 경로를 재사용.
   - 자검: 가능한 단위로 「파일 goal + empty content + tool 0 → failover 시도 또는 명시 실패 문구」.
     실기 Hermes 없이 목으로 분기만 검증해도 된다.

Constraints:
- project.write_file 핸들러·IDE 브리지 대규모 개편 금지.
- goal/followthrough 를 LLM intent 분류기로 교체 금지 (이번 PR).
- 새 의존성·새 에이전트 프레임워크 금지.
- 커밋은 사용자 요청 전 금지.
- 위키 settle / answer_grounding 정책 되돌리지 말 것.

Interface / 건드릴 후보:
- iris/ui/chat/file_write_claim.py (_CLAIM_RE, plan_local_file_writes, named_rel_paths)
- iris/runtime/turn_followthrough.py (_DONE 정합, 빈응답 시 continue 억제 여부)
- iris/ui/window/main_window.py (_gate_chat_completion, _maybe_local_file_create_write,
  _on_chat_finished, failover 연결)
- iris/storage/failover_prefs.py / iris/runtime/model_failover.py (재사용만)
- iris/ui/_check_file_write_claim.py
- iris/runtime/turn_followthrough.py 의 _check (또는 동등 자검)
- (선택) 짧은 _check_write_verify_failover 모듈

Data shape (유지·확장):
- TurnWriteEvidence, GateResult, FileCreateGoal, LocalWritePlan 유지
- LocalWritePlan.kind: skip | ask | write
- plan_local_file_writes 이름 출처: goal 우선, 비면 assistant 단일명만

검증 (모두 통과):
.venv\Scripts\python.exe -m iris.ui._check_file_write_claim
.venv\Scripts\python.exe -m iris.runtime.turn_followthrough
관련 failover/자검이 있으면 함께.
수동(가능하면): Agent ON + 도구 안 쓰는 모델로 「테트리스 코드 작성해줘」
  → 펜스+이름 있으면 파일 생김, 없으면 CHAT_ONLY 또는 명시 실패/failover.

Out of scope:
- Hermes ReAct 교체, PEV 프레임워크 신설
- LLM goal 분류기
- 탐색기 refresh
- iris_generated.py 허용
```

## 구현 순서 (에이전트용)

1. `_CLAIM_RE` / `_DONE` 보강 + `_check_file_write_claim` 샘플 추가 → 통과  
2. `plan_local_file_writes` assistant 단일명 → 자검 통과  
3. `_on_chat_finished` 빈응답·허위완료 + 파일 goal 분기 → failover 또는 명시 실패 → 자검  
4. 사용자에게 검증 증거만 보고. 커밋은 요청 시.
