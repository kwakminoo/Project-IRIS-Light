# Prompt: 제목·루틴·인수인계도 채팅과 같은 스트림을 쓴다

기준: `docs/code-review/다중채팅-동시작업-2단계-분석보고서.md` 5절·7절, `docs/prompts/다중채팅-동시작업-2단계-보안프롬프트.md`.

```text
Context:
- 2단계 본 경로는 들어가 있다. 슬롯이 런타임 id를 기억하고, HermesChatWorker.run은
  set_inference_model을 부르지 않으며, provider가 있으면 광고 이름이 하나여도 요청 모델명을 유지한다.
- 빈 자리는 backend_call._hermes다. 제목·루틴·인수인계가 여기서 set_inference_model을 부르고,
  provider 없이 stream_chat을 보낸다.
- 채팅 워커의 호출 모양은 이미 있다.
  target이 있으면 stream_model = target.model, provider = target.provider.
  provider가 있을 때만 stream_chat(..., provider=)를 넘긴다.
- 세션 헤더는 넣지 않는다. 잠금 표와 worktree는 이 수정과 한 묶음으로 넣지 않는다.

Goal:
1) _hermes가 set_inference_model을 호출하지 않는다.
2) _hermes가 채팅 워커와 같은 조건으로 provider를 넘긴다.
   타깃이 있고 provider가 있으면 그 값. 없으면 키워드를 생략해 resolve_request_model을 유지한다.
3) 모델 필드는 업스트림 이름이다. 런타임 id를 model에 넣지 않는다.
   route.target.model을 그대로 쓴다. 채팅 워커가 하는 것 이상을 풀지 않는다.

Constraints:
- HermesChatWorker, choose_turn_model, HermesModelSyncWorker, stream_chat 본문은 고치지 않는다.
- ollama 경로와 api 경로의 collect_reply는 고치지 않는다.
- MAX_CONCURRENT 10, CAP 8, 전환 시 취소 금지는 유지한다.
- 메일 패널을 ChatRunMap에 흡수하지 않는다.

Interface:
- backend_call._hermes만 바꾼다.
- 인수인계 테스트의 허메스 더블은 set_inference_model 기록을 성공 조건으로 쓰지 않는다.
  성공 조건은 stream_chat에 들어간 model과 provider다.

검증:
- 보안 프롬프트의 검사와 같다.

.venv\Scripts\python.exe -m unittest tests.test_request_model tests.test_handoff_summary_worker tests.test_hermes_model_failover
.venv\Scripts\python.exe -m iris.ui._check_conversation_switch_cancel
.venv\Scripts\python.exe -m iris.ui._check_turn_followup
```
