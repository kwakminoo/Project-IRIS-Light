# Prompt: 파일 생성 「말로만 완료」 1~5 구현

기준: `docs/code-review/파일생성-말로만완료-원인.md`  
범위: 개선안 순위 **1~5**만. 순위 6(탐색기 refresh)은 이번 프롬프트에 넣지 않는다.

```text
/poteto-mode Feature

Context:
- Hermes 켠 채팅에서 모델이 project.write_file 을 호출하지 않고
  「생성했습니다 / 지금 생성합니다」만 말하면 디스크·IDE·구조창에 파일이 없다.
- 구체(_busy)는 턴이 끝나면 멈춘다. 도구 왕복이 없으면 돌지 않는다.
- MCP 실제 도구는 mcp__iris_control__iris_invoke 뿐이다.
  project.write_file 은 iris_invoke 의 action 이름이다.
- settle_completion_claim / _gate_chat_completion 은 현재 no-op 이다.
  과거 「답변끝-고정문장-제거」로 전면 통과를 고정했다.
  이번엔 파일 생성 허위 완료만 다시 막는다. 위키·검색·일반 답 게이트를 되돌리지 않는다.
- decide_followthrough 의 tool_ok=0 + 완료 주장 → continue 는 위키 저장 목표만 해당한다.
- _handle_image_code_pipe 는 False. _pending_local_vibe_prompt 는 Hermes 턴에서 비운다.
  펜스→파일 전면 폴백은 복구하지 않는다 (IDE 연출 충돌).

Goal (1~5):

1) 허위 완료 정정
   - 턴 종료 표시 직전에, 이번 턴에 project.write_file 성공
     (_note_tool_file_write / verified path / tool ok 줄)이 없는데
     답 본문이 파일 생성·작성·저장·「처리 완료」류를 주장하면
     채팅 표시를 CHAT_ONLY("채팅에만 있고 파일은 만들지 않았다")로 바꾸거나
     원문 끝에 그 한 줄을 붙인다. (둘 중 하나로 통일. 권장: 원문 유지 + 정정 한 줄)
   - settle_completion_claim 또는 _gate_chat_completion 중 한곳에만 둔다.
     위키 settle_wiki_claim / answer_grounding 은 건드리지 않는다.
   - 자검: 도구 없는 「생성했습니다」가 성공만으로 남지 않는다.
     _check_file_write_claim.test_claim_without_tool_is_not_success 기대를 뒤집는다.

2) 파일 목표 followthrough
   - decide_followthrough 에 스크립트/파일 생성 목표를 넣는다.
     예: 사용자 goal 에 「생성」「작성」「스크립트」「.py 만들어」 등 +
     완료 주장 + tool_ok_count==0 → continue (위키와 동일, CAP 유지).
   - FOLLOWTHROUGH_UTTERANCE 는 파일에도 맞게 쓰거나 분기한다.
     「완료라고 말하지 말고 이번 턴에 iris_invoke action=project.write_file 을 호출하라」.
   - 자검: turn_followthrough._check 에 파일 생성 케이스 assert 추가.

3) 넛지 이름 혼동 제거
   - hermes_memory_nudge.py 규칙 12(및 관련)를
     mcp__iris_control__iris_invoke → action=`project.write_file` 전체 경로로만 적는다.
   - 「ok 와 디스크 path 없이 생성·작성했다고 말하지 말 것」을 파일에도 명시.
   - _MARKER 버전 bump (예: v25 → v26). MEMORY 재동기 경로가 있으면 그대로 타게 한다.
   - SOUL/스킬 iris-vibe-code 에 같은 혼동이 있으면 한 줄만 맞춘다. 대량 개편 금지.

4) UI 증거
   - Hermes tool_progress / iris_invoke / project.write_file ok|err 줄이
     LiveActivity(또는 기존 _live_activity)에 항상 보이게 한다. 이미 있으면 누락 경로만 메운다.
   - 채팅에 도구 0회인 턴은 활동 로그로 「도구 호출 없음」을 남길 수 있다 (한 줄).
   - 구체는 tool round-trip 동안 PROCESSING/강조가 유지되면 좋다.
     없으면 _busy 가 도구 progress 구간에도 풀리지 않게만 최소 수정.
   - 새 위젯/대시보드를 만들지 않는다.

5) Hermes 의존 완화 (좁은 로컬 쓰기)
   - 조건이 모두 맞을 때만 Iris가 project.write_file 을 직접 호출한다.
     a) 사용자 목표가 파일/스크립트 생성이다.
     b) 이번 턴 assistant(또는 이미 확정된 펜스)에 실행 가능한 코드 펜스가 있다.
     c) 이번 턴 project.write_file 성공이 없다.
     d) rel_path 를 사용자가 말했거나 펜스/요청에서  unambiguously 알 수 있다
        (5-1.py 등). 모르면 쓰지 말고 묻는다. iris_generated.py 발명 금지.
   - 여러 펜스 + 여러 파일명이면 이름과 1:1로만 쓴다. 애매하면 쓰지 않는다.
   - open=true 기본. project_root 는 기존 work_root_for / 바인딩 세션 규칙을 따른다.
     workspace 불일치면 기존 err 를 사용자에게 보이게 하고 조용히 삼키지 않는다.
   - 전면 펜스 폴백·이미지 파이프 부활 금지. 이 경로는 「이미 코드가 있는 생성 요청」만.

Constraints:
- 순위 6(createFile 후 navigator refresh) 하지 말 것.
- 위키·메일·검색·answer_grounding 의 「모델 문장 통과」정책을 되돌리지 말 것.
- project.write_file 핸들러 내부 로직을 대규모로 바꾸지 말 것. 호출·게이트·넛지·UI 증거 쪽.
- 새 의존성 추가 금지.
- 커밋은 사용자가 요청하기 전에는 하지 말 것.

Interface / 건드릴 후보:
- iris/ui/chat/file_write_claim.py (settle_completion_claim, CLAIM_RE, CHAT_ONLY)
- iris/ui/window/main_window.py (_gate_chat_completion, _on_chat_finished, followthrough 연결,
  선택적 로컬 write 훅)
- iris/runtime/turn_followthrough.py (파일 목표 + _DONE 확장 + _check)
- iris/system/hermes_memory_nudge.py (규칙 12, 마커 버전)
- integrations/hermes-skills/.../iris-vibe-code/SKILL.md (한 줄 정합, 있을 때만)
- iris/ui/_check_file_write_claim.py
- iris/ui/_check_ide_request_tools.py (기대 갱신)
- (선택) tool_progress → activity / 「도구 호출 없음」 한 줄

Data shape (먼저 정하고 코드):
- TurnWriteEvidence: 이번 턴 write 성공 여부 + verified_path (있으면)
- FileCreateGoal: goal 문자열이 파일 생성 의도인지 bool
- GateResult: display, suppress_followup_write (기존 유지)
- decide_followthrough 반환: continue | stop | ask (기존)

검증 (모두 통과할 것):
.venv\Scripts\python.exe -m iris.ui._check_file_write_claim
.venv\Scripts\python.exe -m iris.runtime.turn_followthrough
.venv\Scripts\python.exe -m iris.ui._check_ide_request_tools
.venv\Scripts\python.exe -c "from iris.system.hermes_memory_nudge import _MARKER; assert 'v26' in _MARKER or True"
  (실제 bump 한 버전 문자열로 assert 맞출 것)
가능하면:
.venv\Scripts\python.exe -m iris.ui._check_chat_render_ide_trigger

완료 정의:
- 1~5 각각 코드 + 자검으로 증명된다.
- 보고서 docs/code-review/파일생성-말로만완료-원인.md 의 조치 1~2에 해당하는 동작이 있다.
- 사용자에게 변경 파일 목록·검증 출력을 보고한다.
- 커밋/PR 은 하지 않는다 (요청 전까지).
```
